## 二、管道改进项（由实测反哺）

### P-1 生成物/产物噪音是最大普遍问题（10/15 项目命中）

archify 生成的 HTML 图（7 个项目各 9–13 页、每页 358 符号、`viewerText` fan-in 52、页间相似 254）、构建产物入库（CookMyFridge `site/`、StarMarkDesktop 之外的多个 docs/_build）、压缩 vendor 库（digitaljs.js 5675、excalidraw.min.js 1944、tailwind.cdn 746）——**这些占了各项目 50%–98% 的索引符号**，且大量制造假 findings（similar_to 噪音主体）。

**改进**：S1 索引后增加"产物目录启发式检测"报告——对满足特征（页面符号数高度一致 358×N、`.min.js`/`-rendered.html`/`_build`/`dist/` 命名、同 hash 副本）的目录输出提示，建议用户排除；xcheck 对压缩 JS 的调用提取分歧（archify 项目 cbm_only 45083）可先按 `.min.js`/单行超长文件降权。

### P-2 非代码仓库识别缺失

HomeWork（6372 个 AI 生成内容文件）导致 CBM 按代码索引，超内存预算失败（budget 3583MB / peak 3988MB）。precheck 阶段若能按扩展名分布（JSON/HTML/PDF 占比 >90%、无构建系统、无源码入口）提前判定"内容仓库"，可直接给出"不适用"结论，省去一次大内存索引尝试。

### P-3 CBM 符号共享假象

archify 实测中 `test/joint-layout-contract.test.mjs` 的 `requestAnimationFrame` fan-in 1000，但该文件仅 329 行、真实 CALLS 37——CBM 对跨文件同名符号（浏览器全局桩）合并计数产生假热点。dossier 的 hotspots 视图可加"文件内调用占比"列辅助人工快速识别此类假象。

### P-4 分析器环境三条实录（跨 cache 冲突谱系完整）

本轮分析实际遇到的环境事件链：Qoder CBM 会话冲突（R-G 已录）→ Qoder 关闭后活跃 daemon 切换到 `D:\cbm-cache`（screen-translator 首跑拒绝后对齐成功）→ HomeWork 内存预算保护。**CBM 单 daemon 跨 cache 硬拒的行为在真实工作流里高频出现**——建议上游（work/cbm-upstream-bug-report.md 已有底稿）补充"daemon cache 路径"到错误消息的 `requested cache` 一行旁，方便一眼对齐。

### P-5 值得保留的正面信号

- 死代码候选检出极稳：13 个代码项目全部 0 假阳性（无一误报）；
- similar_to 在生产代码内零误报（所有真发现——UI 窗口四胞胎、escapeHtml 双实现、CookMyFridge site/web 双轨、四项目假阳性均已被人工核实为真）；
- 单文件 6532 行（app.js）/11299 行（protocol.rs）级别的巨石均被符号分布+热点正确暴露。
