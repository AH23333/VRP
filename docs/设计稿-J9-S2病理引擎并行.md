# 设计稿：J9 S2 病理引擎并行

状态：**待批准**（2026-11-19 起草；构想 v11 §J9"stdlib 进程池并行扇出"落地稿；J10 前置已落——#170 perf.jsonl 四阶段基线，本稿另补 S2 侧计时实底）

## 1. 现状与增量（诚实盘点）

- **编排面唯一**：`vrp s2`（cli.py `cmd_s2`）四引擎**串行**——`s2_astgrep.scan → s2_deadcode.scan → s2_p4.scan → s2_jscpd.scan`，共享单 rw 连接，输出四段聚合 JSON。mutate 侧独立：`s2_mutate_run.run` 三引擎（mutmut/stryker/cargo-mutants）按语言（py/ts/rs）分选 targets 串行跑——与四引擎无共享编排。
- **大仓实底计时**（tree-sitter-analyzer，2026-11-19 本机 dogfood，记档不钉值）：
  - astgrep **10.73s**（9 条规则×全仓扫描串行，5709 findings）
  - deadcode **2.77s**（纯 SQL 候选查询+写 1069 行）
  - p4 **37.66s**（knip skipped——无 package.json；vulture 单子进程全仓扫描 772 行）
  - jscpd **4.46s**（单子进程 2664 clones）
  - **串行合计 ≈55.6s**；瓶颈是 vulture（37.7s 地板）与 astgrep（10.7s）
- **引擎互相独立性实核**：四引擎只读 ETL/CBM 派生静态面（symbols/edges/usage_hints/test_linkage/cbm 镜像表），只写**各自** findings source（s2-astgrep/s2-deadcode/s2-knip/s2-vulture/s2-jscpd）与**各自** discrepancy_ledger category——读写面零交叉，这是并行安全的结构性前提。
- **子进程治理底座已齐**：`procs.run_tree`（树杀 #84 孙进程孤儿纪律/低优先级 #147 BELOW_NORMAL+nice 15/`normal_priority` 豁免位 #149）；s6_transact 只读调 `dead_code_candidates`（SQL）不涉引擎编排。

## 2. 并行层级选择（正面回应"进程池并行扇出"）

### 2.1 引擎级四并发（采纳）

四引擎各占一线程并发跑，墙钟 = max(astgrep, deadcode, p4, jscpd) ≈ **37.7-40s**（串行 55.6s，**-28~-32%**）——vulture 地板决定上限。

### 2.2 astgrep 规则级扇出（否决，诚实记档）

9 规则内扇出可把 astgrep 10.7s→~2s，但引擎级并发下 astgrep 已被 vulture 完全遮蔽（max 不变）；嵌套池（4 引擎×9 规则）复杂度+子进程风暴，收益为零。否决。

### 2.3 p4 引擎内 knip/vulture 并发（否决）

同被引擎级遮蔽（TS 仓 knip 与 vulture 多数仓只活一个）；保持 `scan` 单体不改。否决。

### 2.4 线程池而非进程池（构想字面偏离说明）

并行实体本就是各引擎 spawn 的**子进程**（ast-grep/jscpd/vulture/knip）——父侧线程只在 `communicate` 等待（GIL 释放），`ThreadPoolExecutor` 即真并行；`ProcessPoolExecutor` 需 pickle 面+每 worker 重建连接，纯增复杂度零增并行度。学 cargo test 的"并行调度+默认线程数设计"**思想**而非字面形态。

## 3. 数据访问与写序（SQLite 并发纪律）

- **每引擎线程自建连接**：`sqlite3.connect(facts, timeout=30)`（busy timeout 显式 30s——实际 commit 窗口毫秒级，30s 是病态余量非预期值）；各连接建用同线程，无跨线程共享，`check_same_thread` 不触。
- **写面互不交叉**：四 findings source+四 ledger category 各归一引擎——每 source 的行序由单引擎单线程确定（与串行逐字相同：rows 按同序构建、单 executemany 落库）；**跨 source 的 rowid 交错序会漂移**，但消费面（render/dossier/gate 查询）均按 source/键显式分组排序，不依赖跨 source 插入序——红线绑定的下游产物不受影响。
- **读面并发**：rollback journal 多读者+写者 commit 瞬时 EXCLUSIVE——busy 等待覆盖；s2 期间读的都是 ETL 静态面，无长写竞争。

## 4. 错误契约与确定性

- **全任务跑完不抢跑取消**（取消使失败复现面噪声化）；跑完后按引擎固定序（astgrep→deadcode→p4→jscpd）抛**首个**异常——与串行首错同引擎同消息同 traceback 面。
- 结果装配同序：`result/dead/p4/p2` 聚合 JSON 与串行恒等；stats dict 各键为计数聚合，与执行序无关。
- 低优先级保持：四并发子进程仍是 #147 BELOW_NORMAL/nice 15——不抢交互前台。

## 5. mutate 三引擎不并行（边界版图正面回应）

- **#149 实证**：mutate 是时序敏感测量——BELOW_NORMAL 在饱和负载下使 borderline 变异体在 Killed/Timeout 间漂移（stryker idempotent 7!=4，单跑绿）；三引擎并发互相饱和负载=主动制造 #149 修掉的测量污染。**保持串行+normal_priority。**
- 构想 v11 §J9 注"mutate 三引擎低优先级语义在并行下保持"成文与 #149 同日，按 #149 实证为准（mutate 已豁免低优先级，非低优先级语义）。
- 附带理由：三引擎共享 repo 工作目录产物面（`.mutmut-cache`/stryker 报告/cargo outcomes+`target/` 构建锁），并发另有产物面互踩风险——双重理由，范围外诚实记档。

## 6. 红线核对

- 静态产物字节级一致：s2 写入面每 source 行序与串行逐字同→同 facts.db 查询面→下游产物字节级不变。
- 零第三方运行时依赖：`concurrent.futures.ThreadPoolExecutor` stdlib。
- 确定性：并行不改任何行内容/行内序/输出 JSON；测试对拍串行 vs 并行逐面恒等。
- 无服务端/无前端构建链：不触。

## 7. 成本与测试面

- **实施面小**：procs.py 新共享助手 `run_thunks`（定界线程池+定序+首错序，~30 行）+ cli.py `cmd_s2` 改造（每引擎任务自建连接+池调度+同序装配，~30 行）+ **四个 s2 模块零改动**（scan 签名不动，连接由调用方传入）。
- **新测试 ~8-10 件**：`run_thunks` 单测（结果定序/首错定序/max_workers 生效/单任务退化/空任务）；cmd_s2 串行 vs 并行等价对拍（逐 source findings 行序+ledger+stats+JSON 恒等，monkeypatch run_tree 家族注入可控假引擎）；`VRP_S2_WORKERS=1` 逃生门；错误传播序；计时不倒退冒烟。
- **dogfood**：tree-sitter-analyzer before/after 计时记档（不钉值，#153 环境方差纪律）。

## 8. 决策点（需批准）

- **D1 并行层级=引擎级四并发**；规则级扇出与 p4 内并发否决（收益被 vulture 地板遮蔽，§2.2/2.3）。
- **D2 线程池非进程池**：并行实体是子进程，父侧 communicate 释放 GIL；stdlib 零依赖（§2.4）。
- **D3 逃生门 `VRP_S2_WORKERS`**：未设=引擎数（4）；`1`=串行回退（诡异环境/复现调试；与 VRP_CHILD_PRIORITY 同命名族）。
- **D4 错误契约**：全跑完+固定序首错（与串行同面）；不抢跑取消（§4）。
- **D5 mutate 三引擎不并行**（#149 时序污染实证+repo 产物面共享，§5）；范围外记档不改码。
- **D6 等价判据**：串行 vs 并行逐 source findings 行序+ledger+stats+`vrp s2` JSON 输出恒等；下游产物字节级同（红线，§3/6）。
