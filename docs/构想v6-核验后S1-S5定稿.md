**取代 v5 的选型部分**；v4 的数据流/闸门/事务框架保留，仅按核验结论修订挂点。核验记录见 v5 的"v1 工具的处置"。

## 0. 前提变化：核验结论一览

| 仓库 | 状态 | 核验结论 | 在本方案中的身份 |
|---|---|---|---|
| codebase-memory-mcp (CBM) | 47.9k★，当日仍活跃 | CLI + SQLite 双通道，162 语言 + 13 语言 Hybrid LSP，运行时证据接口 | **S1 基座（直接用）** |
| code-atlas (lusiem) | 停更 3 月，单人 | 32 工具/25 语言/8 LSP，证据分级落库，verify_changes，预算化 dossier | **精确性补充 + 交叉验证**（pin 0.6.0 + fork 预案） |
| Unwind (nearform) | 活跃，公司背书 | 稳定符号 ID、manifest−docs 集合差、grill 证据闸门、五态等价类 | **范式库（抄机制，不引代码）** |

| lsp-mcp | 停更 20 月，POC | LSP 桥接机制 | 仅设计参考 |
| repolect | 3 天弃坑 | 树+图映射设计 | 仅设计参考 |
| Archify（本地） | v3.2.0 | 断言验证+渲染交付层，零代码分析 | 范式库 + 下游交付层 |

三个关键判定：

1. **CBM 可以直接用**：接入面（CLI `--format json` / 直读 SQLite）、schema（nodes/edges/coverage/observed）、工程质量（SLSA L3、8 平台二进制）全部达标。S1 不再需要拼装 scip-* + ast-grep + ctags 的多 provider 矩阵。
2. **facts.db 从"合并引擎"降级为"薄派生层 + 注解宿主"**：v4 时代的边投票合并是为多对等 provider 设计的；CBM 成为基座后，其他来源降为交叉验证，投票机制简化为**差异登记簿**（discrepancy ledger）。
3. **自建面从 v5 的"四件"收敛为"三件"**：ETL（薄）、校验器组（Unwind 范式落地）、freeze/dossier 编排。LSP 驱动器从"自建"降为"暂缓"（CBM Hybrid LSP 覆盖 13 语言，其余语言先用结构层，缺口实测后再决定）。

## 1. 总体数据流（修订版）

```
仓库 (git snapshot: commit + dirty state)
 │
 ▼
S0 precheck ── scc 语言普查 + 命令发现(build/test/lint/typecheck) + CBM 版本锁定
```

## 2. 证据等级体系 v2（五级）

v4 的四级（index-exact > lsp-exact > family-gated > heuristic）修订为五级，CBM 的类型化边模型按下表映射：

| 级别 | 来源 | 典型边 |
|---|---|---|
| **runtime-observed** | CBM `observed_calls`/`observed_paths`（ingest_traces） | 实测调用对 |
| **compiler-exact** | scip-*（仅离线 eval 用作金标准） | 编译级 occurrence |
| **hybrid-lsp** | CBM CALLS/CALL_REFERENCE，且语言 ∈ Hybrid LSP 13 语言 | 解析后的调用/引用 |
| **structural** | CBM DEFINES/IMPORTS/CONTAINS/INHERITS/TESTS 等结构边 | tree-sitter 确定性提取 |
| **heuristic** | CBM 非 Hybrid LSP 语言的 CALLS（文本回退）、USAGE（歧义保守降级） | 名称匹配 |

两条设计规则不变：AI 注解不产生边、不改证据等级；等级取**边上的最弱环节**（事务影响面推断时按最低等级声明）。

**改造点（ETL 内）——开放问题 #1 已实测解答（2026-11-02）**：CBM 的 CALLS/CALL_REFERENCE 边 properties **携带逐边 resolver 溯源**（`strategy` + `confidence` + `candidates` + `args` + `line`），证据分级走**精确路径**：`lsp_*` 系（confidence 0.85-0.97）→ hybrid-lsp；`import_map`/`same_module`/`qualified_suffix`（0.9-0.95）→ structural-resolution；`unique_name`/`suffix_match`（0.01-0.75）→ heuristic。注意两点：USAGE 边**无** strategy/confidence（仅 callee 名），统一按 heuristic 处理；约 1.6% 边 properties 为空，按边类型默认级兜底。实测分布见 §12.3。

## 3. S1 提取：CBM 单源 + code-atlas 交叉验证

| 组件 | 角色 | 接入方式 | 产出 |
|---|---|---|---|
| **CBM** | 基座：结构 + 语义 + 覆盖缺口 + 运行时证据 | ① CLI 子进程 `--format json`（管道用）；② 直读 SQLite（ETL 用） | CBM SQLite（28 种节点标签 / 42 种边类型） |
| **code-atlas** | 交叉验证 + 精确补充 | `npx @lusiem/code-atlas@0.6.0 index` → 直读其 `.code-atlas/index.db`（edges 带 confidence+provenance） | 逐边对照结果 → discrepancy_ledger |
| **scc** | 语言普查（进 S0） | CLI 子进程 | 语言/规模统计 |
| **profiler 转换器**（可选，后置） | 运行时证据采集 | pprof / py-spy 等格式 → `cli ingest_traces` | observed_calls 增强 |

管道形态决策：**全走 CLI，不走 MCP**。理由：可审计（每条查询可落日志）、可重放、不绑定 Agent 会话；MCP 模式仅留给人工调试。

**S1.5 ETL（本方案最大的自建件，纯 ETL 无算法风险）**：

- `nodes` → `symbols`：qualified_name 采纳为**规范化 ID 的 join key**（CBM 已保证 project 内唯一）；铸 fid = `project + qualified_name + 定义内容哈希`（重命名容忍靠锚点集 + 事务 declared_moves，v4 设计不变）
- `edges` → `edges`：按 §2 映射表分证据等级；`SIMILAR_TO` 不进边表，直通 S2-P2 findings；`FILE_CHANGES_WITH` 进历史耦合表（dossier 用）
- `index_coverage` → `coverage_gaps`：parse_partial / parse_unusable / skip 三态**原样保留**——这是免费的 fail-closed 覆盖声明，同时是 G1 的输入
- `observed_calls/paths` → `runtime_evidence`
- `file_hashes` → 增量键（ETL 可按文件粒度重跑）

**铁律**：任何注解/事务/闸门记录**永不键控 CBM 的 node id**——上游源码注释明示 node id 每次重索引会轮换（他们自己的 observed_calls 也因此按 qualified_name 键控）。我们与 CBM 的唯一契约面 = qualified_name + SQLite schema（版本守卫：ETL 启动时校验其 store_meta 的 schema 版本）。

## 4. S2 病理检测：引擎照旧，数据源换了

| 病理 | 引擎 | 相对 v5 的变化 |
|---|---|---|
| P1 风格接缝 | **ast-grep**（YAML 规则 + `sg scan --json`） | 不变；规则编写辅助用 CBM `search_code`/`search_graph` 加速人工迭代 |
| P2 近似重复 | **CBM `SIMILAR_TO`**（MinHash+LSH，Jaccard 已在边上） | **jscpd 降为 eval 比对器**；阈值在 AI 生成代码上的调优是知识资产（开放问题 #2） |
| P3 原型残骸 | **ast-grep**（命名规则）+ facts.db 入度 join | 不变；CBM 死代码候选（零入边函数）作交叉输入 |
| P4 依赖膨胀/死代码 | **knip / deptry+vulture / go deadcode / jdeps** | 不变（CBM 不做"未用依赖"分析）；结果与 CBM 死代码候选一起进差异登记簿 |
| P8 同义反复测试 | **Stryker / mutmut / cargo-mutants** + 自写预算采样器 | 不变；CBM `TESTS`/`TESTS_FILE` 边可为采样器提供"符号→测试"预筛，降低变异预算。**语言缺口实测确认（§12.4）**：TESTS 边对 pytest/Go 正常（tsa-eval 31631 条），对 **JS/TS（jest/vitest 匿名回调风格）系统性为 0**——闭包归因 helper 仅支持 Python（pass_tests.c #1548）。JS/TS 项目的符号→测试预筛需 ETL 自建（USAGE 边 + 测试路径判定重建） |

S2 全部 findings 写 facts.db，锚定 qualified_name + 行号 + 内容哈希；每条 finding 必须引用真实代码位置（Unwind grill 闸门范式：**引用不出来就拒绝入库**）。

## 5. S3 规范化：定位修订

facts.db 表清单分两组：

**派生组**（来自 CBM，可随时重建）：symbols、edges、coverage_gaps、runtime_evidence、history_coupling、test_linkage。

**自有组**（我们的增量，唯一不可重建资产）：annotations（AI 注解，经校验器）、transactions（T1-T4 + declared_moves）、findings（S2）、gate_results、discrepancy_ledger、dossier_views、baseline。

校验器组（Unwind 范式落地，三件）：

1. **锚定校验**：注解必须锚到存在的 qualified_name + 行号窗口，内容哈希不符则 stale（Unwind detect-changes 的 structural/cosmetic/stale 分类照抄）
2. **覆盖率校验**：注解覆盖率 = symbols − annotated，按 qualified_name 集合差计算（Unwind verify-coverage 的 manifest−docs 机制），缺口列表回喂 S6 补注
3. **证据闸门**：AI 产出的每条 finding/注解声明必须引用 facts.db 中真实存在的节点/边/行号，merge 时机械校验（grill 的"quote real code at a real line or rejected"）

**差异登记簿替代边投票**：CBM 边为基线事实；code-atlas 的 lsp 1.0 边、（eval 中）scip 的编译级边与之对照，不一致只登记不裁决——裁决留给人工或 S6 的 AI 复核。这把 v4 边投票引擎（最大的自建风险项）砍成一个 SQL 表 + 对照查询。

## 6. S4 freeze：骨架不变，加两个 CBM 联动

- 执行 S0 发现的命令（build/lint/typecheck/test），采集覆盖率，变异审计存档——v5 方案不变
- **联动 1**：freeze 时用 `index_repository(persistence: true)` 产出 `.codebase-memory/graph.db.zst` 团队工件作**基线图快照**——后续事务的结构判据用 `compare_graphs` 对比"基线图 vs 事务后重扫图"，替代自写结构 diff
- **联动 2**：`detect_changes`（scope: "tests"）提供变更→受影响测试映射，G3 可做选择性测试执行（CBM 官方声明其 Smart CI 门禁仅 C/C++ 收敛，**我们只把它当预筛信号，不当门禁**——门禁仍由完整测试命令兜底）

## 10. 风险与对冲

| 风险 | 对冲 |
|---|---|
| CBM 单厂商（DeusData） | 契约面收窄为 qualified_name + SQLite schema；Provider 接口保留，替换成本 = 重写一个 ETL；版本 pin + schema 版本守卫 |
| CBM C 代码库难贡献 | 只消费不改；二进制分发渠道锁定（Windows: scoop/winget，CI 缓存） |
| code-atlas 停更 | pin 0.6.0 + fork 预案；其 SQLite schema 简单可自维护；失败路径 = dossier 降级、G4 少一项（不致命） |
| ~~CBM 边无逐边 resolver 溯源~~ | **已消除（§12.3）**：strategy+confidence 逐边在库，ETL 走精确路径 |
| CBM USAGE 边通用名噪声 | 实测确认（§12.6）：`store`/`config` 等常见标识符的 USAGE 边会跨文件泄漏；ETL 将 USAGE 归 heuristic 级且不参与影响面推断，仅作检索线索 |
| TESTS 边 JS/TS 缺口 | §12.4；ETL 对 JS/TS 自建符号→测试关联 |
| SIMILAR_TO 对 AI 生成代码的召回未知 | **阈值地板已实测（§12.5）**：发射阈值 ~0.95，高精度零低段召回——P2 查重召回需 jscpd 类引擎补位（回归 v5 双引擎结论，但角色互换：CBM 主精度、jscpd 补召回） |
| CBM 缓存目录安全检查拒绝嵌套路径 | **实测踩坑（§12.2）**：Windows 上缓存目录祖先链 ACL 必须全是可信 SID（user/SYSTEM/Admins），D 盘默认继承的 Authenticated Users ACE 会被拒；**解法：缓存目录直接放盘根**（`D:\cbm-cache`，组件遍历跳过盘根、无祖先需要检查） |

## 12. 实测记录（准备工作日志，2026-11-02，Windows 本机）

### 12.1 安装与索引冒烟

- CBM **0.12.1**（比 README 的 0.11.0 新），官方 install.ps1 装至 `%LOCALAPPDATA%\Programs\codebase-memory-mcp\`；注意安装器**默认自动注册进本机所有 agent**（.claude.json/.codex/config.toml/Cursor 等），用前检查裁剪
- CLI 事实：**`--format json` 仅读工具支持**，`index_repository` 不接受（首跑误判踩坑）；索引用 `--repo-path`（非 `--repo`），支持 `--name`（覆盖路径派生丑名）、`--mode full|moderate|fast|cross-repo-intelligence`、`--async` + `--status`、`--persistence`（graph.db.zst）
- Cypher `query_graph` 的 `--query` 内嵌单引号在 PowerShell 下易碎，**稳定方式 = `--args-file <json文件>`**
- 索引实测 ①（code-atlas-lusiem，TS）：**1887 节点 / 6608 边 / 6.2s**，parse_partial 2 文件（带行号的诚实缺口信号：src/parsing/loader.ts:55、fixture .h）✓

### 12.2 CBM 缓存目录迁移（C 盘 → D 盘）踩坑

- CBM 支持 `CBM_CACHE_DIR` 环境变量（application.c:1070），本机设用户级变量指向 `D:\cbm-cache`
- **安全检查机制（源码走查 ipc.c）**：缓存目录祖先链每个组件须"用户私有"——DACL 全为可信 SID（当前用户/SYSTEM/Builtin Admins/TrustedInstaller），**observe-only 不自修**；D 盘默认从根继承 `Authenticated Users:(M)` + `BUILTIN\Users:(RX)`，任何 `D:\子目录\...` 嵌套路径全被拒（报错仅一句 "could not load saved runtime settings"，无细节——诊断体验差，靠源码定位）
- **解法**：缓存目录直接放**盘根**（`D:\cbm-cache`）——组件遍历从索引 3 起跳过 `D:\`，无祖先要检查，仅最终目录须 owner=当前用户（运行时检查自会重写其 DACL）
- 铁律级教训：**CBM 的报错信息与 ipc_validation_detail 经常不透出**，诊断靠读源码；ETL 崩溃兜底要预设这条路径
