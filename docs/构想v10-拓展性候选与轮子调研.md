# 构想v10 — 拓展性候选与轮子调研

> 状态：发散清单（未立项）。方法论：**先找轮子再决定造/学/绕**——每项标注候选轮子与判定。
> 基线：v0.1.2（S0-S8 全管道+21 语言执法+AI 梳理层+MCP 30 件+测试 3030）。
> 优先级口径：甜点=低成本高确定性；硬核=差异化能力；探索=不确定收益。

## A. 时间维度（当前全是快照，零历史纵深）

### A1. 架构腐化时间线
- **是什么**：`git log` 逐 commit（慢仓采样）回放 ETL→耦合度/环数/死代码随时间的演化曲线——"这个仓库哪天开始烂的"；fid_ledger 身份史是雏形，缺序列化存储与回放调度。
- **轮子**：
  - **code-maat**（Adam Tornhill，Your Code as a Crime Scene）——git log 挖掘：hotspot/作者/变更耦合（co-change），最接近的思想源；
  - **CodeScene**（Tornhill 商业版）——热点演化+社会性分析（组织耦合），行为参照系；
  - **git-of-theseus**（Erik Bernhardsson）——代码存活曲线（survival analysis）可视化先例；
  - **PyDriller**（Python 库）——commit 级度量计算框架（复杂度/耦合随 commit），可作为校准对照。
- **判定**：**学**（Tornhill 的度量定义：hotspot=chg×complexity、co-change 矩阵）+**造**（ETL 回放调度与 fid 序列化是我们独有的 facts.db 底座优势）。纯 Python 标准库可覆盖。
- **成本**：中。优先级：**中期硬核**（差异化能力，"代码考古"叙事完整）。

### A2. dossier diff 报告
- **是什么**：两次 run 的 dossier 对账→"本版本新增/消除病理、架构变化清单"——release notes 自动素材（v0.1.2 手工做的）。
- **轮子**：
  - **deepdiff**（Python 库）——JSON 树 diff，语义粒度合适但引入第三方依赖，**不引入**；
  - **diffoscope**——递归 diff 框架，形态参照；
  - **jd / json-diff CLI**——输出形态参照。
- **判定**：**绕**轮子（dossier schema 自有，dict 递归对账 ~百行纯 stdlib）。
- **成本**：低。优先级：**短期甜点**（dogfood 直接受益）。

### A3. 漂移预测

> **状态注记**：**前置已实施**（2026-11-21 批④，交接 #202）：drift 复验历史表 `drift_history` 落库（每次 `_revalidate_ingested` 落一行——etl 全量/增量/curate/curate_merge/MCP 五类时刻；git_head 批次锚+复验统计快照；跨 etl 经 OWNED_TABLES 存续；`vrp drift --history N` 读出）。**外推本体留触发池**：历史积累 ≥10 批数据后再看。

- **是什么**：drift 率趋势外推→"curate 工件还能撑几个批次"，提前预警 remap 负债。
- **轮子**：无专门轮子（统计学线性外推即可）；drift 历史数据积累是前置条件（当前 drift 只报当前态）。
- **判定**：**造**（但前置=先给 drift 落历史表，本身是小批）。
- **成本**：低-中。优先级：探索（数据积累后再看）。

## B. 证据源扩展（当前静态为主+traces 单点）

### B4. 测试覆盖对账

> **状态注记**：**已完成**（2026-11-21 批⑤实施，交接 #203；用户睡前授权全权推进——设计稿自批自决 docs/设计稿-B4-测试覆盖对账.md D1-D5 随批定稿）：外部 coverage.py JSON 报告导入（pytest --cov 生产者外部，零依赖红线）→ `test_coverage` 独立表（file_path 键跨 etl 稳定，per label 整批替换，OWNED 存续）→ test_linkage 静态关联 vs 实际行覆盖五桶对账（body 区间 (start_line, end_line] def 行排除——coverage.py 对未调用函数恒报 def 行 executed，import 执行非测试执行；linked_not_covered_measured=「静态说有测试但从不执行」假关联现形）；学 diff-cover 行区间映射+traces #144 独立表对账模式第三次复用；CLI `vrp testcov`。

- **是什么**：pytest --cov 行覆盖导入→test_linkage 静态关联 vs 实际覆盖互查——"静态说有测试但从不执行"的假关联现形；与 traces（#144）同构（独立表+对账三分类）。
- **轮子**：
  - **coverage.py / pytest-cov**——覆盖数据源（.coverage SQLite 格式，解析面清晰）；
  - **diff-cover**——diff×覆盖率对账先例（行级映射逻辑可学）；
  - **Codecov/Coveralls**——SaaS 参照，不引入。
- **判定**：**学**（diff-cover 的行区间对账）+**造**（test_linkage 侧的对账三分类是我们已有的 schema 模式）。
- **成本**：中。优先级：**中期硬核**（test_linkage 23512 行真值已在校准基础）。

### B5. 性能证据导入
- **是什么**：cProfile/py-spy 采样→热点路径与静态 hotspots 视图对账——静态耦合热点与运行时耗时热点的不一致本身就是发现。
- **轮子**：
  - **cProfile**（stdlib）——确定性 profiler，stats 格式解析零依赖；
  - **py-spy**——采样式（生产可用），speedscope 格式输出；
  - **scalene**——CPU+内存复合采样，参照。
- **判定**：**学**（格式解析）+**造**（对账视图）。
- **成本**：中。优先级：探索（Python 优先，多语言性能证据暂缓）。

### B6. 异常/日志聚类
- **是什么**：异常日志→故障路径映射模块→"哪个模块在生产环境最痛"（与静态病理评分加权）。
- **轮子**：
  - **Drain3**（日志模板挖掘，模板化聚类）——日志→模板 ID 的成熟算法；
  - **Sentry**（自托管可用）——异常分组先例（fingerprint/grouping 语义可学）。
- **判定**：**学**（Drain 算法思想——日志模板树）+**造**（模板→模块归属）。日志导入格式先用 Sentry JSON 导出。
- **成本**：中-高。优先级：探索（依赖真实日志样本，dogfood 面窄）。

## C. 执法面深化

### C7. 混仓分治执法

> **状态注记**：**已完成**（2026-11-20 实施，交接 #201；设计稿 D1-D8 全批落地：分治调度（单次清场+逐语言只插不删）/跨语言边 top 100 组上报/status 聚合三态（ok/同态/partial）/表驱动路由/超时全额/assess 文案/单批实施）。

- **是什么**：混仓现在直接 not-enforceable（"py + ts"拒绝）——按语言分治：每语言独立契约集各自执行，跨语言边经 CBM 边关联上报（不参与层判定）。monorepo 微服务仓刚需。
- **轮子**：
  - **Bazel visibility**——多语言 monorepo 依赖可见性规则（目标级 visibility），语义参照；
  - **Nx**（TS monorepo）——项目图+tag 约束（enforce-module-boundaries tag 规则），分治先例；
  - 无专门"混语言架构执法"轮子——**这正是空缺点**（deptrac/ArchUnit/import-linter 全是单语言）。
- **判定**：**造**（21 引擎底座已齐，分治调度是纯组合工作；跨语言边只上报不判定）。
- **成本**：中。优先级：**中期硬核·首推**（唯一"直接拒绝真实场景"的能力缺口；monorepo 是主流形态）。

### C8. 规则表达力扩展
- **是什么**：现在只有 forbidden（层 DAG）——加扇入扇出阈值、命名约定、包距离（抽象度/稳定性度量）规则。
- **轮子**：
  - **deptrac**（PHP）——layers+ruleset+阈值（skip_violations/tags）表达力标杆；
  - **ArchUnit / NetArchTest / ts-arch**——语言内 arch 规则 DSL 家族（命名/分层/依赖规则）；
  - **JDepend**——包距离 D 度量（Martin 稳定性/抽象性原则）的经典实现。
- **判定**：**学**（JDepend 的 D 度量公式+deptrac 的阈值语义）+**造**（规则仍走 structure JSON 声明，不引入 DSL 解析面）。
- **成本**：低-中。优先级：短期甜点偏后（表达力按需扩，避免过度设计）。
- **状态**：**已完成**（2026-11-21 甜点穿插批 #212）——`vrp layermetrics <repo>`（JDepend D 度量公式+deptrac 阈值语义判定学，规则仍走 structure JSON 声明不引 DSL）：per-module/per-layer fan_in（Ca）/fan_out（Ce）=模块间去重边对（DISTINCT (src,dst) 类依赖语义非调用次数；多属 fid 模块对全组合 s7 先例；structure 宇宙外排除噪声地板）+instability I=Ce/(Ca+Ce)（孤立 scope I=None 诚实未定义）；**abstractness 不可推导记档**（facts.db 无修饰符数据——BB2 同源边界，D=|A+I-1| 半面不造 A）；thresholds=structure payload 可选顶层键（curate 不拒未知键）三限值（max_fan_in/max_fan_out/max_instability）违例 rc=1 CI 可用；structure 未 curate 与 stale 区分诚实提示（s7 同语义只消费 active）；命名约定规则面**缓议**（本条自注"表达力按需扩避免过度设计"兑现——无真实需求案例不造轮）。

## F. 度量自身（学 TSA 治理基因）

### F15. precision/recall 基准仓
- **是什么**：人工标注已知违例的标注仓→21 引擎各自查准查全率持续度量（现只有 xcheck agreement 一个间接指标）。
- **轮子**：
  - **tree-sitter corpus**——corpus 测试格式（标注→断言逐例）先例；
  - **Label Studio**——标注工具（标注期用，不入产品依赖）；
  - **CodeXGLUE**——代码任务基准方法论参照。
- **判定**：**学**（tree-sitter corpus 的"标注即测试"形态）+**造**（标注仓结构：fixture 仓+ground truth JSON+引擎跑分 harness）。
- **成本**：中（标注贵，可从 21 个 dogfood probe 仓的已知违例起步——零新增标注）。
- **优先级**：中期硬核（21 个 enforce-probe 仓已有 ground truth 雏形，启动成本低）。
- **状态**：**已完成**（2026-11-21 批⑥，交接 #204）——与构想v13 BB3 合批落地："标注即测试"形态兑现（truth JSON committed 入库受 pytest 守卫保护）；`vrp golden` 双面审计（violations 多集匹配/symbols 五键精确近失）+七件真值集（5 s7 语言+2 ETL pin，dogfood fixture 起步零新增标注）+27 件测试（quick 23+deep 4）；precision/recall 分母零→null 诚实（查准查全率持续度量从 xcheck agreement 单一间接指标升级为对独立真值的双向计数）。
