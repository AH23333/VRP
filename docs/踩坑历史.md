## S3（第四批，2026-11-02）

31. **旧 facts.db 缺新表**：schema 加自有组五表后，已有仓库的 facts.db 不含 annotations/gate_results——validate/gate 直跑即崩 `no such table`。**解法：rw 打开一律 `ensure_schema`（schema 全 IF NOT EXISTS，幂等追加迁移）**。教训：schema 任何变更，所有读写入口都要过 ensure_schema，不能只靠新建库

## S4（第五批，2026-11-02）

34. **Windows `shell=True` 超时是假的**：`subprocess.run(command, shell=True, timeout=N)` 超时只 kill 直接子进程（cmd.exe），**孙进程（npm/tsc/vitest）还握着 stdout/stderr 管道**——communicate 继续阻塞到孙进程自然退出，30s sleep 命令配 timeout=2 实测跑了 30s。**解法：Popen + 超时 `taskkill /PID <pid> /T /F` 杀整棵进程树**（/T=tree；POSIX 对应 start_new_session=True + killpg）。教训：凡 shell 代理执行（shell=True）的超时都必须按"进程树"语义处理
35. **失败定位要读全 stderr**：freeze E2E 四命令全 rc=1，尾部 `'tsc' is not recognized...` ——第一反应"npm 没找到"是错的（PS 里 npm 解析到 npm.ps1，cmd 子进程走 npm.cmd，两者都在）；真凶是**仓库没装 node_modules，脚本内层的 tsc 不存在**。runtime evidence 的价值就在完整尾部——诊断时先读 payload 全文再下结论

## S5（第六批，2026-11-02）

36. **SQL 视图版本漂移**：`CREATE VIEW IF NOT EXISTS` 不会替换已存在的旧定义——schema 改了视图，旧库查询仍是旧语义（且旧定义可能已坏）。**解法：视图一律 `DROP VIEW IF EXISTS` + `CREATE VIEW`**（视图无数据，重建零成本），表保持 IF NOT EXISTS
37. **"死代码"必须按使用边判，不能按任意入边**：第一版 v_dead_code 用 `NOT EXISTS(任意入边)`，实测 0 命中——CONTAINS/DEFINES 类结构边把每个符号都"救活"了。**正确口径与 s2_deadcode 对齐：仅 CALLS/CALL_REFERENCE/MENTIONS/SPAWNS 计为使用**，加 is_candidate 后滤；对数 134=134 才算过
38. **SQLite DISTINCT 聚合单参限制**：`GROUP_CONCAT(DISTINCT col, '|')` 报 "DISTINCT aggregates must have exactly one argument"——DISTINCT 聚合不可带分隔符，用默认逗号或子查询去重
39. **CBM CLI 输出格式**：get_architecture 默认是人类可读 tree 表（`key: value`+缩进表），不是 JSON——`run_cli` 的 JSON 解析直接失败。须 `--format json`（MCP 参数 format:"json"）；其他工具同理，先探一次真实输出再接管道

## S6（第八批，2026-11-02）

42. **CBM 同名 reindex 会正确剪除已删符号**（正面经验，探针实证 23→21 qns）——G1 重扫可直接用 canonical 名 reindex=True，无需每事务专用 CBM 项目名；但**事务失败后 CBM 缓存停留在事务态**，下次 transact 前的 index 会再次 reindex 拉回，无残留危害

## Large Repository Wrap-up E2E (Tenth Batch, 2026-11-02)

48. **_fit infinite loop (scale bug, only explodes on the 66K repository)**: _fit's halving loop has two fatal flaws — the reducible set includes len==1 lists (after [:max(1, 1//2)]==[:1], length never changes), and non-list large fields (GROUP_CONCAT giant strings, nested single-element giant lists) don't participate in shrinking; on the small repo the payload always fits into cap and never touches this branch; on tree-sitter-analyzer (dup clusters members 10KB + SCC largest single component 1023 qns) **infinite loop burns 25 minutes** (each round is a pure-CPU json.dumps loop). Fix: reducible set only takes len>1, when exhausted break and accept exceeding soft cap; at the same time, structurally truncate oversized fields at the source (largest becomes {"size":n,"members":[<=30]}, members substr 300). Lesson: **halving loops must prove "strictly decreasing per round"**; scale bugs aren't exposed by unit tests + small-repo E2E, only real large-repository validation exposes them
49. **When timeouts/hangs occur, suspect budget loops first, not external commands**: the initial 25-minute timeout was attributed to repomix subprocess or MCP watchdog (misjudged direction for half an hour); actually repomix completed in 4s and MCP in 2s. The correct localization method: **staged timing scripts + real-time log flush to disk** (work/dossier_timing.py pattern) — the log's last "start xxx" before the hang is the stuck stage, more reliable than guessing

## Deep Full Test Layer (Eleventh Batch, 2026-11-02)

50. **Three real product bugs caught by deep tests (all invisible in the quick layer)**: (a) `_norm_rel` missed POSIX absolute paths — on Windows, `Path("/abs.py").is_absolute()` is **False** (no drive letter), and `/etc/passwd`-style edits slipped through validation (quick layer only tested `C:/abs.py`); fix = explicitly reject `startswith("/")` after normalization; (b) `v_dead_code` view was polluted by builtins — the view only had SQL coarse filtering, while `dead_code_candidates()` also had `is_candidate` fine filtering (synthetic paths/test paths/dunder/ENTRY_NAMES), and the two criteria drifted; `s5_dossier.dead_code()` consumed the view directly, so things like builtins.print flowed into the dossier; fix = fully SQL-ized all is_candidate rules into the view (etl's ensure_schema rebuilds views each time = automatic migration), big-repo verification 1065=1065 strictly identical; (c) delete-only transactions are **not replayable** — after committed, the file is deleted; re-running the same tx hits G0 "delete target missing" (create/modify are replayable; delete isn't); test locks in this semantic. **Lesson: massive fuzz parameterization (36+ malformed inputs) and criteria alignment assertions (view vs function) are precisely where quick tests lack strength**
 51. **Practical configuration for layered tests**: pyproject `addopts = "-m 'not deep'"` by default excludes deep; quick layer 111 cases / 20s for daily development; `pytest -m deep` 129 cases / 3min real full-external-chain (real CBM+code-atlas+pytest+git, big-repo baseline) run only at phase completion; `pytest -m ''` full 240 cases for acceptance. deep layer sequential E2E (transact_e2e's eleven scenarios have state dependencies) uses session fixtures + definition order; audit tests add "skip if verdicts directory doesn't exist" guards (running order-dependent tests standalone is invalid by design)

## Deep Additional Batch (Twelfth Batch, 2026-11-02, +1071 cases)

52. **SQLite `LIKE` is ASCII case-insensitive, Python `in`/`startswith` is sensitive**: before the view was GLOB-ized, `'Tests/x.py' LIKE '%test/%'` was True (test path misjudged) while Python `is_test_path` returned False—the previous batch's hand-written SQL equivalent translation failed 28 combinations out of 960 (30×32) combination property tests (Tests/TESTS paths × 14 names that should be kept). Fix = replace all `LIKE ... ESCAPE` with `GLOB` in the view (naturally case-sensitive, and `_`/`.` are literals requiring no escaping); 995 combinations verified consistent. **Lesson: hand-written SQL↔Python equivalent translations must pass full-combination property tests; aligning against two real repository datasets is not verification**
53. **vrp self-produced artifacts blocking transactions**: freeze's CBM persistence writes `.codebase-memory/` (user repo without .gitignore) → git status untracked → transact all rejected with "working tree not clean"; and `git_commit_all`'s `add -A` pulls artifacts into transaction commits, polluting history. Fix = `git_clean` parses porcelain exempting self-produced three directories (.vrp/.codebase-memory/.code-atlas, same registry as s5_rawpack IGNORE_PATTERNS); `git_commit_all` runs `reset HEAD --` on the three directories before committing. **Lesson: every directory a tool writes into the user repo must be registered in a unified "self-produced artifact registry" shared by all git hygiene checks**
54. **Multi-step command output has multiple JSON segments (#47 recurring on run/freeze/transact)**: run (precheck/index/etl/xcheck four steps) and freeze stdout consist of multiple `== title ==`+JSON segments; the deep test's universal parser uses `JSONDecoder.raw_decode` to extract matched blocks from each `{` (`_json_blocks`), more robust than "find == line then join". **Lesson: #47's lesson should be generalized into a shared helper, not each test writing its own parsing**
55. **Fixtures must build their own prerequisites (must not depend on test definition order)**: the initial CLI smoke fixture only created the repo without index/etl, relying on earlier tests to lay groundwork—running later tests standalone crashed entirely with missing facts.db. Fix = complete index+etl inside the module fixture (same as the tx_scratch pattern). **Lesson: in deep sequential E2E, "shared state construction" always goes into fixtures; test functions only perform assertions**

## Deep Additional Batch (Fifteenth Batch, 2026-11-02, +45 cases)
