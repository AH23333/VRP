## CBM（codebase-memory-mcp v0.12.1）

1. **缓存目录安全检查**（12.2）：`win_private_directory_tree_secure`（ipc.c）要求缓存目录祖先链 DACL 全为可信 SID（当前用户/SYSTEM/Builtin Admins/TrustedInstaller）；D 盘默认继承 `Authenticated Users:(M)`+`BUILTIN\Users:(RX)` 不可信 → 任何 D 盘嵌套路径被拒，报错仅 "could not load saved runtime settings" 无细节。**解法：缓存目录放盘根**（`D:\cbm-cache`，组件遍历从索引 3 起跳过盘符，无祖先检查）
2. **CLI 事实**：`--format json` 仅读工具；索引走 `--repo-path`+`--name`+`--async/--status`；Cypher `query_graph` 用 `--args-file <json文件>`（`--query` 内嵌引号 PS 下易碎；`--args-file -` 不支持 stdin）
3. **daemon stop** 可能因 committed client 拒绝 → `Stop-Process` 强杀
4. **TESTS 边 JS/TS 系统性为 0**（12.4）：pass_tests.c `cbm_is_test_func_name` 对 JS/TS 仅匹配字面名，jest/vitest 匿名回调被命名为文件路径派生名；兜底闭包归因仅 Python（#1548）。pytest/Go 正常。**解法：ETL 自建**（`should_self_build_tests`，source='etl-js-ts'）
5. **USAGE 边噪声**：通用名（store/config/content）跨文件泄漏 → 只作 heuristic 检索线索（usage_hints），不作结构事实
6. **节点伪行**：`<project>::missed` 伪项目行存在，ETL 按 project 过滤

## ast-grep（@ast-grep/cli 0.51.0）

10. **npx 直跑失败**："could not determine executable to run"——bin 需平台包装包。**解法：`npm install --prefix work/astgrep` 后取 `node_modules/@ast-grep/cli-win32-x64-msvc/ast-grep.exe`**（`sg` 是弃用别名，会打警告）
11. **`$$$` 元变量绝不能经 PowerShell 双引号**——`$$` 被插值吃掉，规则静默变形（本坑连续踩两次：先坏规则文件，再坏 python -c 内联）。**铁律：含 `$` 的命令/脚本一律落文件再执行**
12. **bare-except 规则**：pattern 形式 `except: $$$BODY` 不解析（rc=8）；须走 `kind: except_clause` + `not: has: kind: type`
13. `scan --rule <yml> --json` 的 line 是 0-based；file 为绝对路径（需 relpath 归一）；rc 非 0 时 stderr 有错误详情
14. 语言 = 文件扩展名映射：JavaScript 覆盖 .js/.mjs，TypeScript 覆盖 .ts/.tsx——规则需按语言重复（如 console-log 要 js+ts 两条）

## SQLite / ETL

15. **CBM 实际列名**（防御式猜列失败，13.3）：`index_coverage` = `project/rel_path/kind/detail`；`file_hashes` = `project/rel_path/sha256/mtime_ns/size`。猜列名的"防御"反而引入 bug——**契约明确的表直接硬编码精确列名**
16. **HAVING 不可用于非聚合查询**（sqlite3.OperationalError）——条件放 WHERE EXISTS
17. **GROUP BY substr 后 SELECT 非分组列会取组内任意行**——误导性输出（曾把整包 2474 条误读为单文件）
18. facts.db findings 表需 `source` 列支撑多引擎幂等写入（DELETE WHERE source=X 再 INSERT）

## vrp 自身

19. **cmd_etl 引用不存在的 `args.name`**：`vrp run` 路径掩盖了它，`vrp etl` 直跑即崩。**教训：CLI 每个子命令都要有直跑冒烟（集成测试覆盖路径 ≠ 覆盖命令）**
20. **测试种子数据**：symbols 有 UNIQUE(project, qualified_name)——种子 qualified_name 用文件路径会撞约束；锚定计数要算同一符号被多条 finding 各锚一次（6≠5 是数错了不是锚错了）

## 环境（Windows / 本机）

21. **CBM_CACHE_DIR 会话不可见**：用户级 setx 后，长会话宿主进程早于 setx 启动，子 shell 不继承——逐命令显式 `$env:CBM_CACHE_DIR = "D:\cbm-cache"`
22. **PowerShell 5.1**：`Set-Content -Encoding utf8` 写 BOM；PS 双引号内 `$` 一律被插值（python -c 内联代码也逃不掉）
23. **scc 不可用**（S0 走扩展名普查回退）；node v24.22.1/npm 11.7.0；Python 3.13.0（D:\Python）；sqlite3 3.45.3
24. **D 盘约束**：所有可落 D 的产物落 D（CBM 缓存、npm 沙箱、仓库本身）；C 盘只留系统级安装

## knip / vulture（P4 适配器，2026-11-02 第三批）

25. **knip rc 语义**：0=干净，2=发现问题（非错误）；配置加载失败（如 vitest/config 模块缺失）只 stderr 警告不中断。`--reporter json` 输出 `{"issues":[{file, exports:[], types:[], files:[], dependencies:[]...}]}`——每 issue 一个文件，按类别分桶，exports/types 条目带 `{name, line, col}`（line 1-based，可锚定）
26. **knip `files` 类别陷阱**：未用文件的目标路径在**条目 name** 里，不在 issue.file（issue.file 是 package.json）——归一化时须特殊分支
27. **vulture 无 JSON 输出**：文本行 `path:line: unused <kind> '<name>' (NN% confidence)`，正则解析；`vulture .` 全仓扫描会把 fixtures/测试数据全扫进来——摄入侧按 testsig 过滤（unused-import/variable 在测试路径直接丢，其余保留）
28. **ledger 幂等 category 冲突**：两工具共用一个 ledger category 会互删——每工具独立 category（`p4-cross-check-{tool}`）
29. **交叉语义差异预期**：knip 测未用导出（模块 API 面）、死代码候选测零入边函数、vulture 测未用代码——三者同意率低是**语义差**不是 bug（code-atlas 仓 knip 与死代码仅 2 处同意；tsa 仓 vulture 同意 107/1065）——差异登记簿正是为此设计
