# 事务契约（Transaction Contract）

> 状态：定稿 v1（R1'，2026-11-04）。本文档是 AI（生产方）与 vrp transact（消费方）之间的接口契约，
> 与 `vrp/s6_transact.py` 的 `load_transaction` 逐字段对照；契约变更必须同步本文档与代码。
> 上游设计：构想v7 §1（主流程四环）、§1.5（驱动循环）。

## 1. 定位

- 事务是 **AI 重构的最小可验证单元**：一组文件编辑 + 声明的结构意图，经 G0-G5 五闸门确定性验证，全过才 commit，任一失败原子回滚。
- **AI 的生产在管道外**（LLM 不进 vrp 进程）；vrp 只消费、验证、执行、出 verdict。
- verdict 是 **repair receipt**：每次运行必写 `.vrp/verdicts/<tid>.json`，失败带稳定 G 码；dossier evidence 节自动内嵌未成功 verdict（R1'），AI 下一轮必然看到。

## 2. 事务 schema

```json
{
  "id": "tx-0001",
  "type": "T1",
  "summary": "rename pkg.old.f to pkg.new.f",
  "declared_moves": [{"from": "pkg.old.f", "to": "pkg.new.f"}],
  "edits": [
    {"file": "pkg/a.py", "op": "modify", "content": "<full new file content>"}
  ]
}
```

| 字段 | 类型 | 约束 | 违规报错（load 阶段拒绝，不进闸门） |
|---|---|---|---|
| `id` | str | 非空；文件名安全字符 `[A-Za-z0-9._-]`，其余替换为 `_` | `transaction.id must be a non-empty string` |
| `type` | str | `T1`/`T2`/`T3`/`T4` 之一 | `transaction.type must be one of (...)` |
| `summary` | str | 可选，默认 `""`；进 verdict 与 git commit message | — |
| `declared_moves` | list | 每项 `{from: str, to: str}`（qualified_name） | `each declared_move needs string 'from' and 'to'` |
| `edits` | list | **非空**；每项见下表 | `transaction.edits must be a non-empty list` |

**edits 每项**：

| 字段 | 约束 | 说明 |
|---|---|---|
| `file` | str，repo 相对路径 | 禁绝对路径、禁 `..`、反斜杠自动归一为 `/`；违规报 `edit.file must be repo-relative` |
| `op` | `create`/`modify`/`delete` | 之外报 `edit.op must be one of (...)` |
| `content` | str | `create`/`modify` 必填（**全文覆写**，非增量 patch）；`delete` 忽略 |

**全文覆写语义**：`modify` 的 `content` 是目标文件的完整新内容，不是 diff/patch——生产方必须先读现文件再产全文。

## 3. 档位语义（T1-T4）

| 档位 | 语义 | G4 等价检查 | G5 死码单调 | 确认闸 |
|---|---|---|---|---|
| T1 | 等价重构（重命名/移动，行为不变） | **严格**：removed/added 符号集合必须与 declared_moves 完全一致；声明移动周围的用法边按 move 映射后必须等价 | 否 | 否 |
| T2 | 清理（只删死代码/冗余） | 宽松：不允许 dangling reference（删掉的东西仍被存活代码引用） | **是** | 否 |
| T3 | 修复（行为改变，修 bug） | 跳过（无等价声明） | 否 | 否 |
| T4 | 改进（行为改变，加功能/优化） | 跳过 | **是** | **需 `--confirm`**（MCP 侧不可绕过，返回 needs_confirmation） |

## 4. 五闸门与 G 码对照表

| 闸门 | 检查 | 生产方常见错误 → 失败码 |
|---|---|---|
| G0 | 应用编辑 | create 目标已存在 / modify·delete 目标不存在 / IO 错误 → `gate/G0/apply-edits` |
| G1 | 重扫解析 | 编辑文件含语法错误 → `gate/G1/parse-errors` |
| G2 | 静态检查 | 项目 lint/typecheck 失败 → `gate/G2/static-check` |
| G3 | 测试 | 项目测试失败 → `gate/G3/test` |
| G4 | 等价/引用/结构 | T1 漏声明符号变更 → `gate/G4/undeclared-change`；T2 删掉仍被引用 → `gate/G4/dangling-reference`；T1 边不保 → `gate/G4/edge-mismatch`；code-atlas verify_changes 报 BROKEN → `gate/G4/verify-broken`；未声明的结构变更（difftastic）→ `gate/G4/structural-change` |
| G5 | 死码单调 | T2/T4 引入新死代码 → `gate/G5/dead-code-increase` |

交叉信号：G4 的等价判断由三路独立信号交叉——集合等价（facts.db）、code-atlas verify_changes（BROKEN 即拒）、difftastic 结构 diff（容注释/空白，未声明 token 变更即拒）；工具缺失时对应信号**非阻塞降级**（诚实降级不冒充通过）。

## 5. verdict（repair receipt）

`.vrp/verdicts/<tid>.json`：

```json
{
  "tid": "tx-0001", "type": "T1", "summary": "...",
  "status": "committed | rolled_back | aborted | needs_confirmation",
  "verdict_at": "<utc iso>", "failed_gate": "G3 | null",
  "gates": [{"gate": "G3", "status": "fail", "detail": {"reason": "test", "code": "gate/G3/test"}}],
  "confidence": "low | degraded | high",
  "rollback": ["restored pkg/a.py"],
  "commit": "<sha>"
}
```

- `confidence`：`high` = G3 实测通过；`degraded` = 无测试命令或静态检查跳过；`low` = T4 未确认
- `aborted` = 闸门间崩溃（树已恢复，H1 兜底）
- 读取面：`vrp verdicts <repo> [--tid <id>]`；dossier evidence 节 `last_verdicts`（open = 非 committed，最新 5 条摘要 + open 计数 + failed_codes）

## 6. preview（提交前自查，R1'）

```
vrp transact <repo> <tx.json> --preview
```

- 每条 edit 出 unified diff（difflib，`--- a/... +++ b/...`；create 从 `/dev/null` 起，delete 至 `/dev/null` 止）
- **工具组**：difftastic 可用时附加每 modify 文件的结构信号（`structural: "unchanged"` = 仅空白/注释变更；缺失时 `"unavailable"`，逐文件失败 `"degraded"`，超 10 个文件 `"skipped-cap"`）
- 无闸门、不改树、不写 verdict、不碰 git；任一 edit 前置失败（目标缺失/已存在）→ `ok: false`，rc=1（这正是 G0 会拒的预检）
- `ok: true` 不代表事务会过闸门——只代表可应用；过不过由 G1-G5 说了算

## 7. 生产指南（循环协议摘要）

1. **最小事务**：一个事务一个意图；一次只解决一个病理目标。大重构拆成事务序列（transact-batch 按文件名序消费，遇非 committed 停）。
2. **declared_moves 必须完备**（T1）：漏声明任何 removed/added 符号 → G4 undeclared-change 拒。qualified_name 以 facts.db `symbols.qualified_name` 为准（下钻核实，勿凭记忆）。
3. **先 preview 再 submit**：`--preview` 自查 diff；T4 confirm 前必看。
4. **读 verdict 再重试**：失败先读 `failed_codes`；重试纪律 **≤3 次/事务**（应用层约定），3 次不过换思路或放弃该目标——verdict 历史全量落盘可审计。
5. **T4 人工闸**：MCP/批量路径对 T4 只返回 needs_confirmation；放行只能人工 CLI `--confirm`。

## 8. 取材指南（dossier 七节 × 档位）

| 档位 | 首选取材节 | 用途 |
|---|---|---|
| T1 | repomap、sql_views（hotspots/coupling）、architecture | 定位等价重构点与移动目标 |
| T2 | sql_views（dead_code/dup_clusters）、summary.findings | 定位可安全删除项 |
| T3 | evidence（runtime + **last_verdicts**）、raw_pack | 复现故障与上轮失败上下文 |
| T4 | architecture、repomap、summary.findings | 结构性改进定位 |
| 全档位 | evidence.last_verdicts | **每轮必读**：上轮未成功 verdict，避免重复同类失败 |
