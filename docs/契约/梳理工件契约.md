# 梳理工件契约（slices / structure）

> vrp 拥有 schema（构想v7 §1.6）；AI 是生产方，`vrp curate` 是验收方。
> 本文档是 AI 生产梳理工件的**唯一权威格式说明**——照抄样例，读完验证规则再动手。
> 配套：[事务契约](./事务契约.md)（③环重构）、`skills/vrp-curation/`（生产指南）。

## 0. 总则

- 三层模型：点（annotations，已建）/ 线（slices，本文 §1）/ 面（structure，本文 §2）
- 工件落 `<repo>/.vrp/ai/`（文件形态：`slices.json`、`structure.json`），或经 MCP `curate_submit` 直接提交
- **验收哲学：机器能验证的交给 curate（确定性规则全过才入库），价值判断留给用户（`--reject` 否决留痕）**
- 任一验证不过 → **整文件拒绝**（原子性），收据逐条含稳定错误码；诚实失败优于宽松猜测
- **漂移复验发生在每一次 facts 变更时刻**（F2）：`vrp run`/`vrp etl`/事务 promote（G1）经 etl 钩子、MCP `curate_submit` 经收据 `stale` 节、CLI `vrp curate` 经收据——符号/边漂移者标 `stale`（不删除，可追溯），"假 active" 窗口已关闭
- 同 `slice_id` 重提交 = 幂等覆盖（DELETE 后 INSERT）
- **fid_ledger 身份史**（F1）：etl 记录每个见过的 fid → (project, qualified_name, file_path)（自有表，跨 etl 存续，内容不变零增长）；漂移工件的旧 fid 经身份史反查 qn 再正查现行 fid，得重定位候选（见 §4）

## 1. 线：slices

### 1.1 schema

```json
[
  {
    "slice_id": "checkout-flow",
    "name": "下单结账流程",
    "summary": "从提交购物车到订单落库的主干链路",
    "steps": [
      {"fid": "<sha256>", "role": "entry", "note": "POST /checkout 路由入口"},
      {"fid": "<sha256>", "role": "process"},
      {"fid": "<sha256>", "role": "persist", "note": "订单落库"}
    ],
    "acts": [
      {"name": "入口段", "from_step": 0, "to_step": 1},
      {"name": "落库段", "from_step": 2, "to_step": 2}
    ]
  }
]
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| slice_id | str | ✓ | 全局唯一，非空；幂等覆盖的键 |
| name | str | ✓ | 非空；业务线名（人话） |
| summary | str | ✓ | 非空；一句话脉络 |
| steps | array | ✓ | 非空；步骤序列 |
| steps[].fid | str | ✓ | symbols 表的真实 fid（nav_search/nav_symbol 取） |
| steps[].role | enum | — | `entry` / `process` / `branch` / `persist` / `respond`（缺省 process） |
| steps[].note | str | — | 可选步骤注解 |
| acts | array | — | 可选分幕；无 acts = 单幕 |
| acts[].name | str | ✓ | 幕名 |
| acts[].from_step / to_step | int | ✓ | 步骤下标闭区间 |

### 1.2 验证规则（确定性，全过才入库）

1. 每 `steps[].fid` ∈ facts.db `symbols`（存在性）
2. **相邻 steps 之间在 facts.db 有真实边**（`CALLS` / `CALL_REFERENCE` / `HTTP_CALLS` 任一方向）——严格优先，跨跳即拒
3. `slice_id` / `name` / `summary` 非空
4. `acts`（存在时）边界单调递增、**无缝衔接且覆盖全部 steps**（首幕 from=0，末幕 to=len-1，相邻幕 to+1=from）

### 1.3 拒绝码（收据 `errors[].code`）

| 码 | 含义 | 修正方向 |
|---|---|---|
| `FILE_NOT_JSON` | 文件不可读/非法 JSON | 修语法 |
| `FILE_WRONG_SHAPE` | slices.json 必须是 JSON **数组** | 包一层 `[]` |
| `SLICE_SCHEMA` | 对象结构/必填字段/role 枚举/steps 空非法 | 对照 §1.1 |
| `SLICE_EMPTY_NAME` | name 空 | 补名 |
| `SLICE_EMPTY_SUMMARY` | summary 空 | 补摘要 |
| `SLICE_UNKNOWN_FID` | fid 不在 symbols | 重新 nav_search 取当前 fid（跨事务 fid 会变） |
| `SLICE_MISSING_EDGE` | 相邻 steps 间无边 | 用 nav_callers/nav_callees 找真实相邻符号；不允许跨跳 |
| `SLICE_ACT_BOUNDS` | acts 边界非法/不衔接/未覆盖 | 对照规则 4 |

## 2. 面：structure

### 2.1 schema

```json
{
  "modules": [
    {
      "module_id": "core-graph",
      "name": "图构建模块",
      "responsibility": "从结构提取结果构建符号图",
      "symbol_fids": ["<sha256>"],
      "layer": "domain"
    }
  ],
  "layers": [
    {"name": "domain", "may_depend_on": []},
    {"name": "service", "may_depend_on": ["domain"]}
  ],
  "rules": [
    {"rule": "domain 不许 import ui", "enforcement_hint": "import-linter",
     "from_layer": "domain", "to_layer": "ui"}
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| modules | array | ✓ | 非空；模块划分 |
| modules[].module_id | str | ✓ | 非空唯一键 |
| modules[].name / responsibility | str | ✓ | 非空；人话职责 |
| modules[].symbol_fids | array[str] | ✓ | 非空；模块成员符号 |
| modules[].layer | str | ✓ | ∈ layers；模块所属层 |
| layers | array | ✓ | 非空；层定义 |
| layers[].name | str | ✓ | 非空唯一 |
| layers[].may_depend_on | array[str] | ✓ | 可空；允许依赖的层（DAG） |
| rules | array | — | 可选；架构规则（S7 原料） |
| rules[].rule | str | ✓ | 非空规则文本 |
| rules[].enforcement_hint | str | — | 执法工具提示 |
| rules[].from_layer / to_layer | str | — | 结构化层引用；存在时必须 ∈ layers |

未分配符号属隐式 unassigned，不阻断入库（但 nav_architecture 会报 unassigned_symbols 计数）。

### 2.2 验证规则（确定性，全过才入库）

1. `symbol_fids` 全部 ∈ facts.db `symbols`
2. 模块间 fid **不重叠**（一个符号一个模块）
3. `layers` 的 `may_depend_on` 图**无环**（层序 DAG）
4. `module.layer` ∈ layers；rules 的 `from_layer`/`to_layer` ∈ layers
5. `module_id` / `name` / `responsibility` 非空

### 2.3 拒绝码

| 码 | 含义 | 修正方向 |
|---|---|---|
| `STRUCT_SCHEMA` | 对象结构/必填字段非法（含 modules/layers 空、fid 数组空） | 对照 §2.1 |
| `STRUCT_EMPTY_NAME` | module.name 空 | 补名 |
| `STRUCT_EMPTY_RESPONSIBILITY` | module.responsibility 空 | 补职责 |
| `STRUCT_UNKNOWN_FID` | fid 不在 symbols | 重新取当前 fid |
| `STRUCT_FID_OVERLAP` | 同一 fid 属多个模块 | 一符一模；重划边界 |
| `STRUCT_LAYER_CYCLE` | may_depend_on 有环 | 破环（层序必须 DAG） |
| `STRUCT_UNKNOWN_LAYER` | module.layer 或 may_depend_on 引用不存在的层 | 对齐 layers 定义 |
| `STRUCT_RULE_LAYER` | rule 的 from_layer/to_layer 不在 layers | 对齐 layers 定义 |

structure 是 **state 语义**：单行幂等覆盖（每次提交替换整体）。

## 3. 命令面与工具面

| 入口 | 命令 | 说明 |
|---|---|---|
| CLI | `vrp curate <repo>` | 扫 `.vrp/ai/` 验收入库；任一文件拒收 → 退出码 1 |
| CLI | `vrp curate <repo> --reject <slice_id\|structure> [--note ...]` | 用户否决留痕（status→rejected + decisions 表） |
| CLI | `vrp drift <repo>` | 统一漂移查询面（只读，§4）；stored active 实际漂移 → 退出码 1（对账跳闸） |
| MCP | `curate_submit(kind, payload_json)` | 同验证器；kind ∈ slices/structure；收据带 `stale` 节（提交时复验其余 active 工件） |
| MCP | `curate_slices()` / `curate_structure()` | 读已入库工件（含 status） |
| MCP | `curate_reject(kind, target_id, note)` | 否决留痕（agent 可代转达用户决定） |
| MCP | `curate_receipt()` | 读最近收据（`.vrp/curate-receipt.json`） |
| MCP | `drift_report()` | 统一漂移查询面（只读，§4） |
| nav | `nav_slice(slice_id)` | 业务线下钻（steps 附符号摘要句柄） |

状态机：`active`（可用）→ `stale`（复验发现符号/边漂移，待复梳理）/ `rejected`（用户否决）。
`vrp run` / `vrp report` **不自动触发 curate 入库**（`.vrp/ai/` 不被扫描）；但 `vrp run` 经 etl 钩子自动复验已入库工件（标 stale 不入库）。

## 4. 漂移查询面与重定位（drift_report / fid_ledger）

fid = sha256(project|qualified_name|content_hash)——内容变则 fid 变（契约不变）。
漂移治理三层（R6' 诚实发现 F1/F2/F3 的固化）：

1. **写路径复验**（F2）：每次 facts 重建（`vrp run`/`vrp etl`/事务 promote）与每次 MCP `curate_submit` 都复验全部 active 工件，漂移者标 `stale`——不存在"没跑 CLI curate 所以还 active"的假象
2. **统一查询面**（F3）：`vrp drift` / MCP `drift_report` 逐条给出 active/stale 工件的 `fresh` / `missing_fids`（含候选）/ `missing_edges`；`summary.active_but_drifted` 非空 = 复验链有洞（对账信号，CLI 退出码 1）；`fids_recovered=true` = 内容回退使 fid 复活，原载荷可原样重提
3. **重定位候选**（F1 读出辅助）：`missing_fids[].candidates` 按两层给——
   - `match: qualified_name`：fid_ledger 反查旧 fid 的 qn → 正查现行 symbols 得唯一新 fid（内容轮换，qn 不变——最常见）；此时工件级 `remap` 直接给 `{旧 fid: 新 fid}` 映射
   - `match: same_file`：qn 已消亡（改名/删除）→ ledger 记录的文件域现行符号补位（cap 10，供人工判读），不构 remap
   - ledger 无记录（pre-F 库或未见过该 fid）→ `ledger: false` 零候选诚实返回

**remap 只是提议，不是旁路**：按 remap 改写工件后仍走正常 `curate_submit`（fid 存在性/相邻边/acts 全量重验）；改写时须重新核实业务语义（新 fid 对应的内容是否仍是原意）。

## 5. 生产指南（给 AI）

1. **取材**：dossier 定位 → `nav_search` 拿 fid → `nav_callers`/`nav_callees` 核实相邻关系 → 只把**有真实边的相邻符号**写进 steps
2. **fid 时效**：fid 是内容敏感 sha256——事务提交（promote-etl）后必变；curate 前重新 `nav_search`
3. **漂移后复梳理**：`drift_report` 拿 `remap` 映射 → 机械替换 fid（`match: qualified_name` 候选）→ 核实业务语义不变 → `curate_submit` 重提；`same_file` 候选须人工判读，不许盲替换
4. **被拒后**：读收据 `errors[].code` → 对照 §1.3/§2.3 修正 → 整文件重提（原子性意味着必须整体过关）
5. **不许虚构**：fid 必须来自 nav 族查询结果；无边就换相邻符号，不许硬编
6. **slices 服务重构决策**（③环取材），**structure 服务架构执法**（S7 原料）与 L0 地图
