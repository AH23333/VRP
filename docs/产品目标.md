# 产品目标

## 一句话

面向通用 AI 的 vibe 项目重构分析管道：把 AI 堆出来的仓库变成**有事实基础、可验证、可执行重构**的对象。

## 背景判断

- vibe coding（AI 生成/迭代）产出的仓库有稳定病理谱系：风格接缝（P1）、近似重复（P2）、原型残骸（P3）、依赖膨胀/死代码（P4）、同义反复测试（P8）等——密度远高于人类维护的仓库
- 通用 AI agent 缺的不是推理力，是**可信的项目事实**：符号图、调用图、证据分级、测试关联、病理清单
- 现成工具已覆盖 80% 能力（CBM 索引、ast-grep 规则、code-atlas 交叉验证、Unwind 范式），缺的是管道化的粘合与事实规范化

## 用户与产物

- **主用户：通用 AI agent**（不绑定特定 Agent/MCP 框架）。产物是文件与数据库，不是服务
- **辅用户：人类工程师**。产物同样可读可审计
- 核心产物：`facts.db`（规范化事实层 + 注解宿主）与 dossier（五视图装配），重构事务（T1-T4）在其上执行

## 核心原则

1. **事实与 LLM 解耦**：事实层纯确定性（CLI + SQLite），AI 层只消费与注解，不参与事实生成
2. **一切锚定可验证位置**：每条 finding/注解必须引用真实存在的 qualified_name + 行号 + 内容哈希，引用不出来就拒绝入库
3. **证据分级，不下赌注**：五级证据（hybrid-lsp/structural/usage/heuristic/runtime），差异只登记不裁决（差异登记簿）
4. **小拼接，大复用**：能用现成工具绝不自写；自建面收敛在 ETL、规则集、校验器、装配器
5. **可审计可重放**：全管道 CLI 子进程化，零第三方运行时依赖（Python 标准库）

## 非目标

- 不做 IDE 插件、不做 MCP 优先（管道全走 CLI）
- 不做语言/类型特化（目标项目通用：web/游戏/嵌入式）
- 不做边投票合并引擎（→差异登记簿）
- 不追求一次完美（G1-G5 闸门 + 增量改进）
- 不做渲染引擎（dossier 是信息架构，不是漂亮界面）

## 成功判据（均已达成）

- 两仓 E2E（TS/Python）稳定跑通：交叉验证一致率 71.2%/73.7%，S2 锚定率 99.8%/100% ✓
- 重构事务在 facts.db 上可声明、可验证、可回滚：T1-T4 全场景 E2E + G4 五信号（同符号体内偷改可抓）✓
- AI 拿到 facts.db + dossier 后能产出经闸门校验的重构方案：dossier 七节装配 + 证据闸门收编 ✓

## Dogfood 验证（2026-11-04 首战）

**用 vrp 分析 vrp 自身**——发布后首次实战运行，双战果：

- **抓真 bug**：首跑即撞 CBM workspace 改名 bug（坑 #81——特定路径上下文下 CBM 无视 `--name` 改用路径 slug，11 探针定案）；修复 = 消费 CBM 返回的 `project` 字段（唯一真相源）+ provenance 反查逃生门（`find_cbm_db`）+ 3 快测锁定
- **vrp 自身健康画像**（数据裁决"无重构必要"）：依赖图**零环**（mutual_cycles 0/SCC 0）；xcheck agreement 95.2%；hotspots 在测试基建而非产品代码；真死码 1 处即修（`etl._copy_table_simple`）；S2 自病理 72 findings 全锚定零 rejected（测试代码可接受模式）；dead_code 2 候选全部裁决（1 真删 1 设计性 fixture 保留）

dogfood 的方法论结论：**管道在非验证仓的真实环境里首跑就抓到了 15 个探针都难撞的环境耦合 bug**——数据驱动的健康画像（零环+死码即清+热点在测试侧）证明核心建设收口后的架构无重构对象；将来动的触发条件是数据变化（出现环/热点漂移到产品代码/死码增长），不是感觉。

详细技术方案见《构想v6-核验后S1-S5定稿》（权威版）。
