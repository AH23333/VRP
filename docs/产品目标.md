# 产品目标

## 一句话

面向通用 AI 的 vibe 项目重构管道 + MCP 插件：把 AI 堆出来的仓库变成**有事实基础、可验证、可执行重构**的对象——不让 AI 全读裸代码，认知来自 vrp 分层接口。

## 背景判断

- vibe coding（AI 生成/迭代）产出的仓库有稳定病理谱系：风格接缝（P1）、近似重复（P2）、原型残骸（P3）、依赖膨胀/死代码（P4）、同义反复测试（P8）等——密度远高于人类维护的仓库
- 通用 AI agent 缺的不是推理力，是**可信的项目事实**：符号图、调用图、证据分级、测试关联、病理清单
- 现成工具已覆盖 80% 能力（CBM 索引、ast-grep 规则、code-atlas 交叉验证、Unwind 范式），缺的是管道化的粘合与事实规范化

## 产品形态：主流程四环（构想v7 定稿）

```
① 工具分析 ──→ ② AI 梳理分析 ──→ ③ AI 重构 ──→ ④ 工具分析（回归）
 (vrp run)      (MCP 导航/curate)   (事务契约+     (重跑+verdict 回馈)
 S0-S5 事实层    AI 不读裸代码       transact)      ────────→ 回到 ②
```

- **CLI = 引擎面**（确定性管道），**MCP = 用户面**（AI 接口层，`vrp mcp`）
- verdict 是 repair receipt：失败带稳定 G 码，回馈进 dossier evidence，AI 下一轮必然看到
- 循环由外部 agent 经 MCP 驱动（skills/vrp-loop），人肉 CLI 为底线；vrp 内置 LLM 排除（确定性红线）

## 用户与产物

- **主用户：通用 AI agent**（经 MCP 接口消费；不绑定特定 Agent 框架）。产物是文件与数据库，不是服务
- **辅用户：vibe 开发者（人类）**。两条消费线分开（2026-11-06 定位修正拍板）：AI 消费深层数据（facts.db/MCP 导航接口），vibe 开发者消费 report/chain 用户产物——产物目标是「理解项目、判断 AI 梳理意见是否合理并做决定」：
  - **AI 梳理产出必须进用户主视觉**（模块职责一句话/层次规则/依赖方向），不能只存在库里
  - **S 阶段数据要有翻译层**（病理体检报告：P 码人话图例 + 启发式候选诚实标注），不怼审计清单
  - **深层数据归拢折叠**（IR/SARIF/Datasette 供 AI 与审计者），不占用户主视觉
- 决策点（T4 confirm/curate 验收）保留人工闸
- 核心产物：`facts.db`（规范化事实层 + 注解宿主）与 dossier（多视图装配），重构事务（T1-T4）在其上执行

## 核心原则

1. **事实与 LLM 解耦**：事实层纯确定性（CLI + SQLite），AI 层只消费与注解，不参与事实生成
2. **一切锚定可验证位置**：每条 finding/注解必须引用真实存在的 qualified_name + 行号 + 内容哈希，引用不出来就拒绝入库
3. **证据分级，不下赌注**：五级证据（hybrid-lsp/structural/usage/heuristic/runtime），差异只登记不裁决（差异登记簿）
4. **小拼接，大复用**：能用现成工具绝不自写；每环节是"契约（vrp 拥有）+ 工具组（多项目可插拔）+ 策略（降级链）"（构想v7 §1.6）
5. **分层依赖，可审计可重放**：核心管道（run/transact/curate）零第三方运行时依赖（Python 标准库），全管道 CLI 子进程化可审计；AI 接口层/可视化层是生态接入件，允许 optional extra（如 `pip install vrp[mcp]`）

## 非目标

- 不做 IDE 插件、不做常驻网络服务（MCP server 是本地 stdio 进程；远端 GitHub 仅 push/release，不做 CI/Actions）
- 不做语言/类型特化（目标项目通用：web/游戏/嵌入式）
- 不做边投票合并引擎（→差异登记簿）
- 不追求一次完美（G0-G5 闸门 + 增量改进）
- **不做渲染引擎与服务**（红线，保留）：S8 拍板材料消费现成渲染工具组（archify 钉版本 + 降级链），dossier 是信息架构，不是漂亮界面

## 成功判据（均已达成）

- 两仓 E2E（TS/Python）稳定跑通：交叉验证一致率 71.2%/73.7%，S2 锚定率 99.8%/100% ✓
- 重构事务在 facts.db 上可声明、可验证、可回滚：T1-T4 全场景 E2E + G4 五信号（同符号体内偷改可抓）✓
- AI 拿到 facts.db + dossier 后能产出经闸门校验的重构方案：dossier 七节装配 + 证据闸门收编 ✓

## Dogfood 验证（2026-11-04 首战）

**用 vrp 分析 vrp 自身**——发布后首次实战运行，双战果：

- **抓真 bug**：首跑即撞 CBM workspace 改名 bug（坑 #81——特定路径上下文下 CBM 无视 `--name` 改用路径 slug，11 探针定案）；修复 = 消费 CBM 返回的 `project` 字段（唯一真相源）+ provenance 反查逃生门（`find_cbm_db`）+ 3 快测锁定
- **vrp 自身健康画像**（数据裁决"无重构必要"）：依赖图**零环**（mutual_cycles 0/SCC 0）；xcheck agreement 95.2%；hotspots 在测试基建而非产品代码；真死码 1 处即修（`etl._copy_table_simple`）；S2 自病理 72 findings 全锚定零 rejected（测试代码可接受模式）；dead_code 2 候选全部裁决（1 真删 1 设计性 fixture 保留）

dogfood 的方法论结论：**管道在非验证仓的真实环境里首跑就抓到了 15 个探针都难撞的环境耦合 bug**——数据驱动的健康画像（零环+死码即清+热点在测试侧）证明核心建设收口后的架构无重构对象；将来动的触发条件是数据变化（出现环/热点漂移到产品代码/死码增长），不是感觉。

详细技术方案见《构想v6-核验后S1-S5定稿》（权威版）。
