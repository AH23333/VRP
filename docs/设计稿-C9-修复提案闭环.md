## 3. fixpropose 生成面设计（单 finding 单文件）

- **输入**：`vrp fixpropose <repo> <finding_id>`——按 findings.id 取单条 finding；
  finding 缺失/无 file_path → 诚实拒绝（fixpropose 只服务有文件位置的 finding；
  anchor-only finding 走 agent 路径）。
- **材料**（auto_curate 材料面纪律同型）：
  - finding 全字段 JSON（pathology/kind/source/start_line/end_line/payload_json）；
  - **现文件全文**（带行号檐口，line-number gutter——LLM 产全文覆写必须有完整现文）；
  - 文件超 cap（MAX_FILE_CHARS=100_000）诚实拒绝：「file too large - use the agent path
    (dossier + transact)」——不截断喂半文（半文产全文=幻觉温床）。
- **范围**：单 finding 单文件——edits 必须全部落在 finding.file_path（跨文件修复走 agent
  路径，MCP 消费者有 nav/dossier/transact 全套工具）。单文件范围内 op 只可能是
  modify/delete（create 需目标不存在，与单文件已存在矛盾）。

## 4. 校验器与拒收回执（确定性校验器即工具）

- **形状校验=s6_transact.load_transaction 复用**（单一契约源——事务契约.md 头部约定
  「契约变更必须同步本文档与代码」；fixpropose 不复制契约逻辑）：草案落 attempt 文件后
  load_transaction 校验，ValueError 消息原样入回执 detail（code=PROPOSAL_TX_SHAPE）。
- **加验三条**（fixpropose 特有范围约束，回执码稳定）：
  - `PROPOSAL_WRONG_ID`：draft.id 必须==`fix-<finding_id>`（确定性命名——提案文件名
    与 tid 一致，审计链可从 verdict 反查 finding）；
  - `PROPOSAL_WRONG_FILE`：每条 edit.file（归一后）必须==finding.file_path（归一后）；
  - `PROPOSAL_WRONG_OP`：op 必须∈{modify, delete}。
- **回执驱动重试**≤MAX_ATTEMPTS=3（auto_curate 同型：parse_error/拒收回执均计入 attempt，
  回执 JSON 进 feedback 重试；3 拒诚实 failed，rc=1）。

## 5. 红线核对（C9 红线：修复草案永远走 transact 闸门）

- **信任边界结构化**：fixpropose 的 LLM 输出物理上只能变成 `.vrp/proposals/fix-<n>.json`
  草案文件——不执行、不落库、不碰 git、不起子进程；执行只存在于 `vrp transact`
  （G0-G6 闸门+T4 人工闸 --confirm 照常生效）。
- **import 纪律**：fixpropose.py 对 s6_transact 的引用**仅限 load_transaction 校验器**；
  不 import transact 执行面——census 式源码守卫测试钉死（test_fixpropose.py 内源码扫描：
  s6_transact 引用集合=={load_transaction}、源码无 `.transact(` 调用、无 git/子进程字样）。
- **既有红线全不动**：三红线（静态产物/无服务端/无前端构建链）、零第三方运行时依赖
  （llm_client stdlib urllib）、key 不落盘（LlmConfig.echo 掩码）、facts.db 只读消费
  （不写 findings——提案是文件面产物非库面）。

## 6. 留痕与交付物

- **run 审计目录**：`.vrp/fixpropose/run-<UTC>/`（同秒冲突 -2 后缀，auto_curate 同型）：
  `config.echo.json`（key 掩码）+`01-finding.json`（finding 全字段+file 大小）+
  每 attempt `{NN}-fixpropose-attempt-{n}.request.json/.response.txt/.meta.json/.draft.json/
  .receipt.json` + `summary.json`。
- **交付物**：`.vrp/proposals/fix-<finding_id>.json`（transact 可直接消费：`vrp transact
  <repo> .vrp/proposals/fix-<n>.json --preview` 自查→去 --preview 执行）。
- **防覆写**：交付物已存在→诚实拒绝（保护人工已 review/手改的草案——覆盖=销毁人工工作）；
  `--force` 显式覆盖。run 审计目录永不覆写（每次新 run 目录）。
