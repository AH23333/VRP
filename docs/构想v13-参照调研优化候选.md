# 构想v13 — 参照调研优化候选

> 状态：发散清单（未立项）。源自《参照调研-codegraph双仓.md》（codegraph 78k★/CGC 4.4k★ 双仓学习，2026-11-19）的可移植优化提炼。
> ID 序列：A-Z 已被 v10/v11/v12 耗尽，本批启用双字母新系列（AA/BB）；与前三批正交。
> 方法论反转：前几批是"先找轮子再造"，本批是"从正规项目实测教训中提炼"——每项带参照仓事故锚点。
> 优先级直觉：亮点=AA1/BB1/BB3（MCP 消费面+置信度+审计，直接决定代理消费价值与分析可信度）；甜点=小时级；硬核=需设计稿。

## AA. MCP 消费面（代理适配工程——codegraph 实测教训）

### AA1. 单强工具与成功形状错误契约
- **是什么**：MCP 工具集收敛——默认暴露一个强查询工具（多查询类型聚合，CGC analyze_code_relationships 15 query_type 单工具先例）而非一排窄工具；**可恢复状态绝不返回 isError**——未索引/找不到符号等一律返回成功形状的指引文本（codegraph 实测：`isError:true` 一两次就让代理整个抛弃工具；错误即放弃）。代理引导单源（initialize 响应唯一权威，安装块只指向工具名）。
- **轮子**：**codegraph**（`src/mcp/tools.ts:100-111` NotIndexedError 成功形状；`AGENTS.md` "Adapt the tool"/"错误即放弃"两节；8 工具定义默认暴露 1 的实测结论）；**CGC**（15 query_type 聚合单工具）。
- **判定**：**学**（设计律：适配代理而非改造代理——"让代理已经在调的工具用它已经给的输入做更多事"；措辞引导实验 3 变体全回归的教训）+**造**（VRP MCP server 工具面收敛改造）。
- **成本**：低-中。优先级：**亮点**。

### AA2. 自适应输出预算与 per-tool 限额/超时/截断
- **是什么**：查询输出预算随库规模单调（codegraph 双层预算：调用数 1-5 次/输出 13K-24K 字符，硬顶 ~24K 内联上限防宿主外置文件；"更大档不得更小每文件额度"单调性不变量）；per-tool 结果条数上限+查询超时+截断可见告警（CGC TOOL_RESULT_LIMITS/TOOL_QUERY_TIMEOUTS，超时按真实规模校准并写明出处）；输出预算类魔数必须回归测试钉死（codegraph ITER1/2/3 反复横跳教训）。
- **轮子**：**codegraph**（`src/mcp/tools.ts:265-409` getExploreBudget/getExploreOutputBudget 两函数+单调不变量）；**CGC**（`utils/tool_limits.py`；"168,745 函数图上 find_dead_code 12s→默认 120s=10×"校准法）。
- **判定**：**学**（预算档位与校准方法）+**造**（facts.db 规模查询+MCP 输出打包层，纯 stdlib）。
- **成本**：中。优先级：**亮点**（与 AA1 合批实施更佳）。

### AA3. GCF 压缩编码（token 优化）
- **是什么**：MCP 响应键声明一次+值管道分隔的紧凑编码，降 token ~62%（CGC 实测，前沿模型 100% 可读，环境变量 opt-in，无解码器回退 JSON）。
- **轮子**：**CGC**（`CGC_OUTPUT_FORMAT=gcf`；`utils/gcf_encoder.py`）。
- **判定**：**学**（编码语义）+**造**（dossier/report 的 MCP 输出面加可选编码层）。
- **成本**：低。优先级：甜点偏后（AA1/AA2 落地后收益才显现）。

## BB. 事实质量面（置信度与审计——CGC 自审报告教训）

### BB1. 调用边置信度分层
- **是什么**：edges 表 CALLS 边加 resolution_tier+confidence+label（EXTRACTED/INFERRED/AMBIGUOUS）列——解析确定性显式入图；下游静态分析（死代码判定/环检测/slices）按置信度过滤，AMBIGUOUS 边不参与"必死"判定只参与提示，误报治理从源头解。
- **轮子**：**CGC**（9 级 tier 0.08-1.00 分层+tier≥8 写独立 HEURISTIC_CALLS 表；`resolution/calls.py:65-86`；embedded_schema CALLS 边列）；**codegraph**（edges.provenance 列 tree-sitter|scip|heuristic+合成边 synthesizedBy/registeredAt 元数据——"部分覆盖比没有更糟"端到端原则）。
- **判定**：**学**（分层语义与阈值）+**造**（facts_schema edges 迁移+ETL 解析路径标注；schema 迁移走既有面）。
- **成本**：中-高（动 schema+ETL 标注面）。优先级：**亮点/硬核**（需设计稿）。

### BB2. 死代码置信度三级+reason
- **是什么**：死代码产物从二值"无引用即死"升级为 low/medium/high 置信度+每条可读 reason——五类误报源显式排除（dunder/测试钩子/入口名/override/装饰器→low-medium；排除规则**整词匹配**防 `name CONTAINS 'main'` 误杀 `domain_check`/`remainder` 类事故）。
- **轮子**：**CGC**（`code_finder.py:55-81` `_classify_dead_code_confidence`+`code_finder.py:20-25` 整词匹配事故注释；#1332）。
- **判定**：**学**（分级规则与五类误报源）+**造**（s2 deadcode/timeline dead_code_candidates 产物面加 confidence+reason 字段，纯下游改造不动 schema）。
- **成本**：低-中。优先级：甜点偏前（BB1 的先行独立件——不动 schema 先在产物面验证价值）。

### BB3. Golden 准确率审计矩阵
- **是什么**：ETL/解析变更评估从"跑通+计数"升级为"对 golden 的准确率矩阵"——missing/spurious 双向计数+per-language 记分卡；**铁律：审计必须对独立真值，禁止循环完美门**（CGC 自审："导出与自己比"给出 21/21 PASS 假象，与真实 CALLS 准确率 84.6% 冲突；手工改过的 golden 不落盘=自欺）。
- **轮子**：**CGC**（`CGC_CALL_GRAPH_AUDIT_REPORT.md` 21 语言记分卡；INCONSISTENCIES ID 78-83 meta 自省；审计工具本身流失的教训——审计工具必须入库受测试保护）。
- **判定**：**学**（记分卡形态与双向计数）+**造**（verify 双仓 golden fixture+ETL 对拍审计脚本，进测试面）。
- **成本**：中。优先级：**亮点**。

### BB4. ETL 健康面（IndexHealth+不变量自愈）
- **是什么**：ETL 后校验双件——①健康检测："哈希没变但符号没了"类漂移（codegraph #2336：内容哈希相等≠产物完好，needsReindex/parseErrors 分类）②不变量自愈后处理（CGC repair_missing_contains_links：索引自检 File→CONTAINS 缺失并回填、删除后清无 path 孤儿——把"删除留 9 个孤儿节点"类 bug 变成自动修复）。
- **轮子**：**codegraph**（`src/types.ts:295-306` IndexHealth）；**CGC**（`pipeline.py:380-387` repair；E2E BUG-005 删除孤儿事故）。
- **判定**：**学**（健康面字段与不变量清单）+**造**（ETL 尾部 invariant 自检清单：每个 Function 必有所属 File/无 dangling fid/edges 端点存在等——查询式断言，失败响亮报错或自愈记档）。
- **成本**：中。优先级：甜点偏后（J8 已证行集等价，此为纵深防御层）。

### BB5. 并发产物确定性排序 checklist
- **是什么**：字节级可复现红线的工程化保障——任何并行步骤（解析/查询/写入）的产物归并处显式排序，"last-writer-wins/first-match-wins becomes nondeterministic" 从数据流剔除；checklist 化进 census/guard 面（新并行代码点必须过"归并确定性"审查项）。
- **轮子**：**CGC**（`pipeline.py:234,308-318` 两次按 path 排序+注释明言；asyncio.as_completed 教训）。
- **判定**：**学**（模式）+**造**（checklist 文档化+现有并行点审计：s2 四并发/procs.run_thunks 归并已确定，需审计其余并行面）。
- **成本**：低。优先级：甜点。

### BB6. A/B 评估防侧信道（dossier 方法论）
- **是什么**：评估产物（dossier/评分）的 A/B 验证方法论——**控制臂必须防工具侧信道污染**（codegraph 教训：WITHOUT 臂 26/28 次通过 Bash 摸到 CLI，"控制臂不是控制臂"）；每臂 ≥2 次取中位；三反馈指标（驻留上下文占用/下一步动作充分性/字节分配效率）；低显著度渠道（措辞/描述）改变不了代理行为，别投入。
- **轮子**：**codegraph**（`scripts/agent-eval/` 双臂封 CLI 守卫；`docs/benchmarks/agent-eval-feedback-metrics.md`；residual-context-occupancy 诚实披露先例）。
- **判定**：**学**（方法论）+**造**（dossier 验收的 A/B 协议文档+脚本，本地可执行）。
- **成本**：低-中。优先级：甜点偏后（dossier 面下次大改时配套）。
