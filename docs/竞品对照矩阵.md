## 一句话对照

| 工具 | 官方一句话（引文） | 我们的定位差异 |
|---|---|---|
| SonarQube | "verifies code... checks every change for bugs, vulnerabilities, and maintainability issues, applies your quality gates"（质量门禁+安全验证平台） | VRP 不做安全/taint/SCA；VRP 的问题是"这个仓该往哪重构"（结构优先），不是"这段代码有没有 bug" |
| CodeScene | "CodeHealth™, the scientifically validated metric predicting defects"（行为代码分析+技术债可视化） | VRP 学其行为分析视角（co-change），但 CodeScene 是托管服务/商业产品，VRP 是单仓 CLI+离线 |
| deptrac | "static code analysis tool for PHP that helps you communicate, visualize and enforce architectural decisions"（PHP 分层执法） | deptrac 单语言（PHP）+声明式层规则；VRP 是多语言管道（facts.db 汇聚）+AI 梳理层 |
| import-linter | "allows you to impose constraints on the imports between your Python modules"（Python import 契约） | 同上：单语言（Python）+import 约束专项；VRP 的 S7 执法跨语言且由 facts.db 统一供给 |

## 能力对照表

以各家公开声明为准；"VRP"列为当前实现（详见 README/交接文档）。

| 维度 | SonarQube | CodeScene | deptrac | import-linter | VRP |
|---|---|---|---|---|---|
| 定位 | 代码质量/安全验证平台 | 技术债管理+行为分析 | 架构层执法 | import 架构约束 | 静态重构管道（结构优先） |
| 语言面 | 官方称 45+ 语言 | 未公开逐语言清单 | PHP | Python | 多语言经 CBM+code-atlas+ast-grep 链 |

| 分析基座 | 自研分析器（rules） | 行为代码分析（git 历史+代码度量） | nikic/php-parser | Python AST | facts.db（SQLite 单文件，多引擎汇聚） |

## 生态位结论

1. **与 SonarQube**：问题域不同（bug/安全 vs 结构重构）。VRP 的 SARIF 输出可与其互补（VRP 出结构 finding，SonarQube 出质量/安全 finding）。
2. **与 CodeScene**：方法论同源（都信"代码数据要连接历史与结构"）；形态相反（服务端 vs 离线 CLI）。VRP 的 co-change/数字画像学其思想，实现走纯 stdlib 离线路线。
3. **与 deptrac/import-linter**：这两者是我们 S7 执法面的"单语言前辈"——层声明格式（depfile/contracts）的形态参照见构想 v12-W20 轮子调研；VRP 的差异是语言广度+facts.db 统一供给+AI 梳理层。
4. **诚实边界**：对家在各自领域更成熟；VRP 的差异化只在"多语言结构重构管道+离线+AI 消费"这个交叉点上。这个交叉点是否真实存在需求，由 dogfood/实测报告回答，不由本文回答。
