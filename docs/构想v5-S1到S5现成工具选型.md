# 构想 v5：S1–S5 的现成工具选型与改造方案（组装优先，不从零实现）

> **2026-11-01 更新**：六仓库核验完成（见下文"v1 工具的处置"），选型已按核验结论重构——**最新定稿见《构想v6-核验后S1-S5定稿.md》**，本文的选型表格保留为核验前的历史方案。

对应 v4 的 S1-S5，逐阶段给出：现成工具 → 用法 → 需要的改造 → 成熟度风险。原则：

1. **优先"CLI 子进程 + JSON 输出"的松耦合接入**（升级换代不牵连我们），只有算法层复用才 import 源码库。
2. **成熟度门槛**：优先广泛使用、活跃维护的工具；v1 提到的小众工具（codebase-memory-mcp、code-atlas、tree-sitter-analyzer、repolect）降级为"待验证 provider 候选"，不作地基——它们的输出 schema 与维护状态需先核验。
3. **自建只留四件**：适配器组（薄 glue）、S3 规范化核心、LSP 驱动器（薄）、dossier 装配（薄）。全部是工程活，无研究风险。

## S1 提取：四个 provider 全部有现成引擎

| 层 | 现成工具 | 用法 | 改造量 | 成熟度/许可 |
|---|---|---|---|---|
| 精确层 | **scip-typescript / scip-python / scip-java**（Sourcegraph SCIP 索引器） | CLI 子进程，产出 SCIP protobuf（真实编译级定义/引用/调用） | 自写 SCIP→facts.db 适配器（protobuf 解析 + occurrence 换算，约几天） | 生产级（Sourcegraph/Cody 在用）；Apache-2.0（核验） |
| 精确层（Go） | **lsif-go**（成熟）/ scip-go（较新，待核验） | 同上 | 同上 | 生产级 |
| 精确层（Ruby/Kotlin） | scip-ruby / scip-kotlin | 同上 | 同上 | **实验性**——核验后决定，不满足就走 LSP 驱动 |
| 精确层（Rust/C/C++/C#） | 无批量索引器 → **LSP 驱动器**：rust-analyzer / clangd / OmniSharp | 自建薄驱动器（见下） | 驱动器自建，但**协议客户端不从零写**：用 `vscode-languageserver-protocol` + `vscode-jsonrpc`（npm，VS Code 官方库，无数无头工具在用） | 驱动器约几百行，纯编排 |
| 结构层（全语言地板） | **ast-grep**（`sg scan --json`，tree-sitter 引擎） | CLI 子进程 | 写提取规则（符号/结构/contains），引擎零改造 | 很成熟（MIT）；tree-sitter 生态 |
| 符号层（残余语言） | **universal-ctags**（`--output-format=json`） | CLI 子进程 | 直接映射，几乎零改造 | 极成熟（GPL-2.0，子进程调用无传染问题） |
| 语言普查（进 precheck） | **scc** | CLI 子进程 | 零 | 成熟 |

**改造方式统一**：每个工具实现 v4 定义的 `Provider` 接口（`extract(paths) → RawFacts`），适配器职责 = 原生 JSON/protobuf → nodes/edges 行 + 证据等级。**不改上游一行代码。**

**v1 工具的处置（已核验，2026-11-01）**：v1 提到的全部五个工具均已找到真实仓库并核验完毕，此前"疑似虚构"的判断撤回（漏检原因是 GitHub 搜索不曝光 0-star/无描述仓库）。

- **code-atlas**（lusiem/code-atlas，clone 于 `verify/code-atlas-lusiem`）：**核验属实且超预期**。README 声明逐项对上源码——正好 32 个 registerTool（src/tools/）、25 语言、`edges` 表内建 `confidence REAL + provenance(index|lsp|engine)`（src/db/schema.ts），即**证据分级直接存在存储层**，与我们的证据等级设计几乎 1:1；`verify_changes`（src/analysis/verify.ts，BROKEN/CHECK/INFO 三级 findings，以 git HEAD 为基线）就是现成的 miswire 审计；`change_impact` 带 affected-tests 反推；npm 包已发布（@lusiem/code-atlas 0.6.0，`npx` 即可用），MIT，47 个测试文件 + CI。**可整体作为一个复合 provider 接入**——"结构地板 + LSP 精确"二合一，覆盖 S1 精确层（TS/Py/Go/Rust/Java/Kotlin/C#/C++ 共 8 个 LSP）+ 结构层（25 语言）+ 部分 S2（verify_changes/find_dead_code）+ S5（repo_map/context_pack 即预算化 dossier 雏形）。**风险**：单人项目（Lusiem，50 commits），2026-07-07~07-27 三周集中开发后停更至今，0 star/0 fork——bus factor=1。处置：fork 固定 + 直接读它的 SQLite（schema 简单清晰，ETL 迁移成本低），停更可自维护。
- **codebase-memory-mcp**（DeusData，47.9k stars，活跃——最后提交即核验当日，社区 PR 至 #1731）：**已深验（2026-11-01），六者中最强，建议升为 S1 基座主选**。v1 描述属实且被低估：
  - **接入形态完全符合我们的偏好**：每个 MCP 工具都有一等 CLI 命令（`cli <tool> --format json`，stdout 专职结果、stderr 进度），且存储为标准 SQLite（`~/.cache/codebase-memory-mcp/`），facts.db ETL 可直接读库或子进程消费，两种方式都零改造上游。
  - **schema 干净且可直接消费**（src/store/store.c:344-493）：`nodes(id, label, name, qualified_name, file_path, start/end_line, properties)` UNIQUE(project, qualified_name)；`edges(source_id, target_id, type, properties)` UNIQUE 四元组去重；28 种节点标签、42 种边类型。另有 `file_hashes`（sha256+mtime 增量）、`index_coverage`（**逐文件诚实缺口**：parse_partial/parse_unusable/skip 三态——我们的 fail-closed 覆盖声明，人家已实现且注释里明确"coverage is metadata about the graph, not part of it"）、`observed_calls`/`observed_paths`（**运行时 trace 落库，按 qualified_name 键控而非 node id**——node id 重索引会轮换，稳定 ID 设计与我们同构）。
  - **证据模型是"类型化"的**（与 code-atlas 的数值 confidence+provenance 不同）：边类型本身编码解析确定度（`CALLS`=调用点已解析 / `CALL_REFERENCE`=引用唯一解析 / `USAGE`=歧义保守降级），Hybrid LSP（13 语言全量：Py/TS/JS/PHP/C#/Go/C/C++/Java/Kotlin/Rust/Perl）在 tree-sitter 之上精化调用解析——Python 声称惯用代码 ~95% 解析率。
  - **能力覆盖超出 S1**：S2 部分（`SIMILAR_TO` MinHash+LSH 近重复、死代码、`TESTS`/`TESTS_FILE` 边、`FILE_CHANGES_WITH` 共变耦合）；S4 证据层（`ingest_traces` 运行时调用证据 + `detect_changes` git diff→爆炸半径+风险分级+测试影响）；结构 diff（`compare_graphs` 快照对比——我们闸门要的结构判据）；S5 雏形（`get_architecture`、Cypher 只读子集查询）。162 语言 vendored grammar，实测 Linux 内核 28M LOC 3 分钟 481 万节点 772 万边。
  - **工程质量**：纯 C 零运行时依赖，8 平台预编译二进制（Windows 有 install.ps1/scoop/winget/choco），SLSA L3 构建溯源 + Sigstore + VirusTotal 全量扫描 + CodeQL 门禁，npm/PyPI/Homebrew/AUR 多渠道分发。MIT。
  - **风险**：DeusData 单厂商主导但社区规模大；C 代码库二次开发门槛高于 TS（我们的策略是不改上游、只消费，风险可控）；无逐边数值 confidence 列（类型化证据模型替代，ETL 时按边类型映射到我们的证据等级即可）。
  - **处置修订**：从"广度 provider 候选"升级为 **S1 基座主选**——结构层（162 语言）+ 语义层（13 语言 Hybrid LSP）+ 运行时证据层（ingest_traces）+ 部分 S2/S5 一并覆盖；scip-* 降为编译级精确性校验源（进离线 eval），code-atlas 的 LSP-exact 输出作交叉验证与 token 预算化 dossier 补充。
- **Unwind**（nearform/unwind，clone 于 `verify/unwind`）：**核验属实**。`@unwind/core` 确定性扫描器（packages/core，pnpm monorepo，TS，MIT，零运行时依赖）产出 `scan-manifest.json` v1.0.0（packages/core/src/manifest/manifest-schema.ts）：files[]/symbols（functions/classes/exports/imports/definitions/endpoints）/importMap/layerIndex，**稳定符号 ID `kind:filePath:name` 作为 manifest↔docs↔graph 的 join key**——与我们 facts.db 的 ID 铸造设计直接同构；符号级提取 TS/JS、Python、Rust、Java、C# 五语言（structure/ 下五个 tree-sitter extractor，与 v1 声明一致），其余语言文件级；最后提交 2026-10-08（近活动），主作者 Clifton Cunningham（NearForm 旗下，公司背景可信），11 stars。**未发 npm，接入需 clone+build 或 vendor**。**对我们的价值分三层**：① S1 provider 候选（但结构层已被 code-atlas 25 语言覆盖，仅作五语言交叉验证源，即 v2 已定的离线 eval 用途）；② **范式层（主要价值）**——"manifest − docs 集合差"覆盖率验证、grill 的"每条 finding 必须引用真实代码真实行号否则合并时拒绝"（fail-closed 校验器）、增量指纹（structural/cosmetic/added/removed + stale 标记）、rebuild-verification 五态等价类（equivalent/present/divergent/claimed/missing）——这四个机制与我们的 G 闸门/增量重提取/AI 注解锚定设计一一同构，是流程蓝本（v1 §133）之外的具体实现参照；③ **grill 的"谁能回答"分诊**（code-answerable 当场解决，业务问题写成 docs/unwind/questions/*.md 路由给领域专家，未答与双勾保持 open 绝不猜）——我们的 dossier 机制缺这一环，值得吸收。
- **lsp-mcp**（jonrad/lsp-mcp，clone 于 `verify/lsp-mcp`）：**核验属实但不可依赖**。192 stars/29 forks，MIT，TypeScript，单人（Jon Radchenko，62 commits），README 自declared "**POC state**"，开发窗口 2025-02~03 共约 6 周，**最后提交 2025-03-31，停更约 20 个月**。机制：通用 LSP→MCP 桥——config 把 extensions/languages 映射到任意语言 server 启动命令（sample 仅演示 typescript-language-server + pylsp 两例；v0 声称的 Rust/Go/Ruby/Java/PHP/C/C++ 等是"可配置"而非内置）；MCP 工具**从 LSP JSON schema 动态生成**（src/lsp-methods.ts + 244KB protocol schema），即定义/引用/调用层级等全部 LSP 方法透传，与 v0 声明机制相符。**处置**：不进生产管道（POC + 停更 + MCP-stdio 形态，非库非 CLI-JSON）；其"扩展名/语言→server 命令"的配置形态可作自建薄 LSP 驱动器的配置设计参考。S1 精确层维持既定方案：code-atlas 内置 8 个 LSP（自动获取 + provenance 落库）覆盖主力语言，缺口走自建薄驱动器（vscode-languageserver-protocol + vscode-jsonrpc）。
- **tree-sitter-analyzer**：family-gated 逻辑进**离线 eval**（v2 已定），不进生产管道。
- **repolect**：0 star、3 天即弃，仅作 S5 设计参考。

**重器备选（暂不接，记录在案）**：**Joern**（Code Property Graph：AST+CFG+数据流+调用图，JVM/Scala，Apache-2.0）——若后续要做数据流级深度分析（如副作用追踪），这是现成引擎；成本是重量级部署。**Semgrep OSS** 可作 ast-grep 的规则面补充。

## S2 病理检测：引擎全部现成，只自写规则内容

| 病理 | 现成工具 | 用法 | 改造 |
|---|---|---|---|
| P1 风格接缝 | **ast-grep**（YAML 规则 + `--json`） | `sg scan -r rules/` | **只写规则集**（错误处理/日志/命名的模式聚类逻辑），引擎零改造 |
| P2 近似重复 | **jscpd**（多语言克隆检测，JSON reporter） | CLI 子进程 | 簇→node_ids 映射（薄）；变体式重复召回不足时再补 embedding 聚类 |
| P3 原型残骸 | **ast-grep**（命名规则）+ 引用图交叉 | 同 P1 | 规则 + 与 facts.db 入边 join |
| P4 依赖膨胀/死代码 | **每语言一个现成工具，走同一 Provider 接口**：JS/TS → **knip**（未用文件/依赖/导出）；Python → **deptry**（依赖）+ **vulture**（死代码）；Go → `go deadcode`（官方 x/tools）；Java → **jdeps**（JDK 自带） | CLI 子进程 | 各自薄适配器，输出归一为 findings |
| P8 同义反复测试 | **Stryker**（JS/TS/C#）/ **mutmut**（Python）/ **cargo-mutants**（Rust） | CLI 子进程 + 预算包装 | 自写采样器：预算内选变异子集（引擎原生支持的用原生，不支持的外层选文件） |

要点：**检测引擎零自建，自建的是规则与归一化**——这正是知识资产的沉淀位置。

## S3 规范化：无现成，但全是商品化组件

这一层是我们的 schema 和合并逻辑，**没有现成开源项目可替代**（这正是它的护城河属性）。但实现它的构件全部成熟：

- SQLite（存储）+ protobuf/JSON 解析（读 scip / 各工具输出）+ ajv（契约校验）
- 工作内容：ID 铸造、边投票合并（v4 §2）、增量重提取、锚点校验
- 性质：**ETL 核心，最大的一块自建，但无算法研究风险**，可按 v4 §7 顺序逐步落

## S4 freeze：编排自建（薄），底层能力全部现成

- 测试执行：直接 exec precheck 发现的命令（商品化：cross-spawn 等），**不需要测试框架知识**
- 覆盖率采集：现成 per-language 工具（coverage.py / istanbul / gcov），检测到才启用
- 变异审计：S2-P8 的工具复用（Stryker/mutmut/cargo-mutants），freeze 只是给它们加预算与基线存档
- 结论：S4 是**纯编排层**，几百行级别

## S5 dossier：三件现成组件的装配

| 视图 | 现成来源 | 用法 | 改造 |
|---|---|---|---|
| 原始上下文包（文件树+内容） | **repomix**（打包仓库为 LLM 友好单文件，成熟） | CLI 子进程，现成 include/exclude 配置 | 零改造 |
| 结构化视图（token 预算的符号地图） | **aider 的 repomap**（tree-sitter + 图排序的仓库地图算法，Apache-2.0，Python） | **唯一需要 import 源码的组件**：复用其算法，从"聊天上下文"改造为"facts.db 视图"（图排序数据源换成我们的 edges 表） | 中等——这是"改造"而非"包装"；需跟随上游版本 |
| 语义树/分层导航 | **repolect**（若核验属实）：树结构 + 图映射设计参考 | 参考数据结构设计，摘要生成交给 AI 层（v1 已定） | 结构复用、逻辑重写 |
| 图查询视图 | facts.db SQL 视图 | 自写（薄） | 装配 |

dossier builder = 上述三件的装配器：按预算选视图、拼装、输出到 `dossier/`。**自建的是"信息架构"，不是渲染引擎。**

## 许可与耦合风险控制

- 子进程 + JSON 的接入方式使 GPL 工具（ctags）无传染风险，也使任何上游停更可替换（Provider 接口隔离）。
- 唯一深耦合是 aider repomap（import 源码）：控制手段是 fork 固定版本 + 我们自己的薄包装层，算法借鉴重写为兜底方案。
- scip-* 依赖 Sourcegraph 生态：protobuf schema 是公开稳定的，且 `scip` CLI 自带转换能力，风险可控。
