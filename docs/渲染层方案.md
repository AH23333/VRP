## 一、定位变更

- **原定位**（v6 非目标节）："不做渲染引擎"——产物黑箱，用户无法验收 AI 梳理结果，信任链断在最后一公里
- **新定位**：**做报告生成器，不做渲染引擎**。渲染 = 分析结果的可验收性（投影收果），不是展示多样性
- **红线三特征**（守住即重心仍在分析侧）：静态产物、无服务端、无前端构建链
- 依据：分析侧原料链已完备（facts.db 含符号/16 种边/每边 confidence/锚定 findings/五视图），渲染层几乎不需要新数据，需要的是新投影

## 二、核心设计决策（讨论演化链）

1. **AI 从"渲染决策环"挪到"分析产出环"**：archify 官方用 LLM 生成 IR（选颗粒度/取舍/布局）——不可复现、颗粒度漂移、信息丢失无收据。修正：**IR 由确定性 Python 代码生成，AI 只产出业务线梳理数据且必须过锚定验证**
2. **颗粒度规则代码化**：渲染分层规范（L0-L3，见第五节）每层确定性规则，LLM 在任何一层无裁量权
3. **数据颗粒度 ≠ 渲染颗粒度**：AI 梳理的数据是符号级+行级锚定（细于任何图一个数量级）；archify 图是组件/函数级沟通图——图只是降维投影，SARIF（行级红线）/Datasette（全行明细）承接图挤不下的细度
4. **无损投影原则**：细数据→粗图时不许丢——长 slice 分幕渲染（语义边界由 AI 梳理决定）、SRC 证据卡（archify evidence-backed 节点支持 git commit + file + line range，vrp 锚定直接灌入）、兜底投影全量承接

| 投影 | 工具 | 承载内容 | 颗粒度 | 生成方式 |
|---|---|---|---|---|
| 图投影 | **archify**（tt-a1i/archify 93.3k★ Apache-2.0，work/ 沙箱钉版本） | 架构图 / 业务线 sequence / 事务流 workflow / 耦合图 | 组件/函数/调用级 | 确定性 Python 生成 typed JSON IR → `node archify.mjs validate/deliver` |
| 诊断投影 | **SARIF 2.1.0** | findings 病理 → IDE 红线点跳源码（VS Code SARIF Viewer） | **行级** | 纯文本生成（file/start/end/message/rule_id 机械映射），零 UI |

## 四、AI 梳理层——业务线闭环（slices，复用现有资产；点/线/面三层中的"线"）

> "面"层 structure（整体结构/分层/职责/规则提议）与"点"层 annotations（已建）同属 AI 梳理层统一立项（见〇节）；本节先收口"线"层闭环设计，三层共享验证器与入库模式。

```
AI 输入：repomap + 入口锚点（HTTP_CALLS/HAS_BRANCH，两仓实测有数据）+ CALLS 图
AI 产出：slices.json —— 每条 = 有序符号 fid 链 + 语义命名 + 摘要 + 分幕边界
   ↓
确定性验证器（新，模式照抄 ai-gate 证据闸门）：
   ✓ 每个 fid 在 facts.db 真实存在
   ✓ 相邻 fid 之间有真实边（CALLS/HTTP_CALLS，带行号）
   ✓ 命名/摘要非空
   ✗ 任一不过 → rejected（收据记录）
   ↓
验证通过 → slices 入库（annotations 体系：四态 active/cosmetic/stale/rejected，代码漂移自动 STALE）
   ↓
渲染：slices → archify sequence IR（确定性映射，AI 零参与渲染）
```

- **业务线抽取 = 分析（图算法骨架 + AI 语义归纳），业务线渲染 = 报告生成器一节**——前者需单独立项论证（当前最大缺口：slices 作为一等概念管道尚无显式产出），后者随渲染层走
- 图算法骨架：入口锚点 + CALLS 链 + PageRank（骨干排序，已有）+ Tarjan SCC（链穿环防护，已有）
- 业务线还能承载图外的细语义：分支条件（"若未登录走 X"）、数据变换标注（"DTO→domain model"）、每跳 confidence/xcheck 双引擎背书

## 六、工具选型理由与排除清单

**选 archify 的核心理由——工程哲学同源**：

| Archify 机制 | vrp 对应物 |
|---|---|
| typed JSON IR + schema 验证 | dossier.json + ensure_schema |
| repair receipt（稳定 rule codes + subject + evidence） | RULE_CODES 十码 / G4 五信号 / discrepancy_ledger |
| SRC 证据节点（commit + file + line range） | 锚定 annotations + window_hash + git_head |
| atomic validation before delivery / last-good | s5 工件原子写 / freeze baseline |
| truthful interaction（不发明拓扑） | 证据闸门（不许伪造） |
| 单 HTML 离线产物 | freeze 工件哲学 |

**排除清单**：D3.js（=自研引擎）；React/Vue dashboard（前端工程链=引擎）；CBM Lens（是 CBM 的 UI 非 vrp 产物投影）；全 archify 单工具（表格硬塞图渲染器错配）；**archify 官方 agent 生成 IR 用法**（LLM 选颗粒度不可复现——本方案修正点）；Graphviz（静态 SVG 无交互，被 archify 覆盖，暂不引入）。
