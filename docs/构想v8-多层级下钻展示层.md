## 0. 背景与决策记录

### 0.1 起因（用户，2026-11-13）

- 对现行 report 展示效果不满意；
- CBM Lens 试用定案：**3D 渲染卡顿，"视觉好看实际无用"——动态工具路线否决**（同因否决：一张图绘制多个层级导致节点过多，又卡又不实用）；
- 用户提出目标形态：类似 Lens 的 2D 版——多层级 archify 图，每层级只画该层内容并包含业务线，用户沿业务线/模块逐级下钻，最终落到真代码。

### 0.2 用户模型（复述定稿）

**双轴模型**：

| 轴 | 含义 | 呈现 |
|---|---|---|
| 纵向（分解轴） | 项目 = 大部分树状的分解树；第 k 层 = 项目的横向切层；**一次只看一层** | 层级导航（面包屑） |
| 横向（数据流轴） | 每层一张 2D 架构图；节点 = 该层单元；边 = 层内模块间数据流 | archify architecture 图 |
| 业务线（贯穿轴） | 命名的纵向线程，贯穿所有层；每层体现为途经的节点/路径段；**每个节点、每条边可挂 0..n 条线**（相同/不同） | 图内高亮 + 跨层下钻延续 |

- 交互：点模块下钻（下一层图限定在该模块作用域内）；沿业务线下钻（下一层高亮该线）；叶子 = 真代码；
- 性能铁律：**任一时刻只画一张节点有界的图**——这是对 Lens 卡顿与 92 节点竖排长图两处教训的结构性回答。

## 1. 目标与非目标

**目标**：

1. 每层级一张（组）archify 图，图内只画该层内容 + 业务线标注；
2. 业务线贯穿全部层级（slices 复用，投影规则确定性）；
3. 点模块/业务线逐级下钻，终点 = symbols 符号页（真代码，既有）；
4. 三红线全守：静态产物、无服务端、无前端构建链；
5. 复现性沿用 v7 §5.4：同 facts.db + slices → 字节级同 IR；产物头部带 facts.git_head，不带时间戳。

**非目标**：

- 不做动态工具/daemon（Lens 路线已否决）；
- 不引入前端框架工程（React/Vue dashboard 在 v7 排除清单中，维持）；
- 不做渲染引擎（archify 仍是唯一图渲染器；本篇只加"站点组装层"，不碰渲染器）；
- 不改分析侧（S0-S5 零动；S 阶段产物是输入不是改造对象）；
- 不做 3D、不做整仓一图。

## 4. 数据模型

### 4.1 层级树（levels）

- **层级定义**：图层级三级 + 代码页一级，共 L0-L3（对齐 v7 §5.3，但每层落地为页面集合）：

| 层 | 节点 | 边（层内数据流） | VRP 自仓实例 |
|---|---|---|---|
| L0 系统图 | structure.modules（active 时 5-12 个）；fallback = 目录聚合（修缺口 2：必出边） | 模块间聚合边（chain-index depends_on 模式） | 5 模块系统图 |
| L1 模块图 | 选中模块的子结构：子目录/文件簇 | 簇间聚合边 | vrp 模块 → s2/render/curate/nav/schema/… 簇 |
| L2 文件图 | 文件节点 | 文件间真实边（facts.db 直查） | render.py → facts.py 等文件级边 |
| L3 代码 | symbols/*.html 符号页（既有） | — | 行级锚定 |

- **自动推导（确定性）**：L0 从 structure.modules + layers 起（v7 L0 规则原样）；L1/L2 从目录切分 + facts.db 边聚合起。同 facts.db → 同层级树。
- **AI 修正通道（不新开机制）**：层级边界的语义调整 = **structure（面层）修正**——AI 通过既有 curate_submit 通道改 modules/layers 分组；扁平目录/弱结构仓上的分组质量问题（预期痛点）由该通道消化，兜底永远是确定性目录切分 + 诚实标注 "fallback"。
- **推导器输出**：层级树 JSON（node id / 层归属 / 父作用域 / 聚合边表 / 每节点 slices 徽标集合），进 `ir/levels.json`，作为站点组装的唯一输入。

### 4.2 业务线贯穿（slices → 层级投影）

- slices schema 不动（v7 §2.2：有序 fid 链 + acts + 四态）；
- **投影规则（新，确定性）**：slice 投到层 k = 每个 fid 映射到包含它的层 k 最小单元 → 保序去重 = 该层的途经路径；节点徽标 = 途经 slice 集合，边徽标 = 相邻步跨单元的 slice 集合；
- **贯穿是语义不是几何**：一次只看一层，业务线在视觉上不是连续竖线；它的形态是"每层图上的路径标注 + 跨层下钻时的延续"（下钻带 `?slice=` 上下文，下一层图自动高亮该线的投影段）；
- 线 × 层覆盖矩阵 mini-map（侧栏小图：哪条线穿过哪层哪些单元）列为**可选增强**，v1 不做；
- 图内呈现：激活 1-3 条线着色高亮；未激活的线在节点/边上以计数徽标显示（hover/链接展开清单）——避免多线视觉过载。

### 4.3 非树与环规则

- **多父单元**（一子模块被多父引用）：按入口视角局部重复渲染——每个父作用域的下钻图各自包含该子单元，保持单图树状简单；
- **跨枝引用**：同层图内画虚线边，不参与布局计算；
- **层内环**（A→B→A 数据流）：允许，聚合边有环就画环。

### 4.4 节点规模（不设硬上限，懒加载——用户裁决 2026-11-13）

- **单图不设节点数上限**：性能由"一次只看一层"的结构保证，不靠聚合裁剪数据；真值永不因渲染裁剪——对齐 v7"无损投影原则"；
- **懒加载三层落实**：①多页结构天然按导航加载（只取当前作用域页，不预载全站）；②wrapper 页 iframe 嵌图带 `loading="lazy"`；③超长序列沿用 acts 分幕先例（dataflow 已有），分幕页按序翻；
- 聚合仅作呈现选项（用户显式要求时），不作默认；
- 下钻即作用域收窄：每图 = 一个作用域的下一层分解 + 边界端口（外部邻居折叠为单个端口节点，保数据流跨层连续——业务线不断线的关键）。

## 5. 渲染与交互

### 5.1 每层一图（archify architecture IR）

- 每个作用域一张 architecture IR：components = 该层节点（含 sublabel：文件/符号计数），connections = 该层聚合边；
- 布局：**横向分层**（数据流左→右，模块组纵向排布）——pos/size 由我方 IR 生成器确定性计算（坑 #83 已证：validate 不查、渲染必需、我方全权控制）；
- 竖排 dataflow 长图降级为"证据视图"：模块页主视图改为 L1 分解图，dataflow 分幕图改为点击后查看的从属页（数据不丢，主视图让位）。

### 5.2 下钻热区（本篇最大新增件，方案已按实测定形）

archify 产物无组件链接（§3-4），下钻由**组装层 wrapper 页**承载：

```
wrapper 页（确定性模板生成，每作用域一页）
  ├── 面包屑（层级路径 + 当前激活 slice）
  ├── 业务线选择器（链接组：?slice=…）
  ├── archify 图（iframe 嵌同目录产物，loading="lazy"，不碰 archify 内部 DOM）
  └── 热区层 = 绝对定位 <a>（几何 = IR pos/size → 百分比定位）
        ├── 点节点 → 下一层该节点作用域页
        ├── title 提示（模块职责 + 途经业务线）
        └── 纯 HTML/CSS，零 JS 依赖（若裁决选内联微 JS 则仅用于高亮，见 §9-2）
```

- 百分比定位天然免疫 archify 产物的 viewport 缩放（探针 P1 验证，§7）；
- 红线全守：无构建链、无服务端；wrapper 由 Python 模板直出。

### 5.3 业务线高亮

- 激活线：该线途经的节点/边着色（已裁决：极小内联 `<script>` 约 20 行切 CSS class；红线是"无构建链"非"无 JS"）；
- 未激活线：节点角落计数徽标（"3 线途经"），点击展开清单。

### 5.4 降级链（沿用 v7 §0.1-4 先例）

archify 沙箱缺失 / validate 失败 → **Mermaid 层图**（graph LR，横向，Mermaid 原生链接语法天然支持下钻热区同款语义）→ 纯 HTML 列表（保下钻链接不保图形）。全程 rc=0 不阻塞管道。
