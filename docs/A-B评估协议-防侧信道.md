# A/B 评估协议 — 防侧信道（dossier 方法论）

> 立项来源：构想v13 BB6（#205 批⑧ rider，随 C9 修复提案闭环落地）。
> 性质：**方法论协议文档**（评估任何 vrp 消费面产物——dossier/评分/MCP 工具面——的
> A/B 验收前，必须过本协议）；脚本面诚实缓议（见 §5）。
> 参照锚点：codegraph（78k★）双仓调研实测教训，全录《参照调研-codegraph双仓.md》。

## 1. 为什么需要协议（事故锚点）

codegraph 的 A/B 基准方法论是被事故逼出来的：

- **控制臂不是控制臂**：早期 A/B 没封 CLI——WITHOUT 臂 26/28 次通过 Bash 摸到
  codegraph（控制臂的代理自己找到了被评估工具，两臂污染同源，对比失义）。
- **低显著度渠道无效**：instructions/description 措辞类微调改变不了代理行为
  （codegraph 3 个措辞变体引导实验全部回归）——在这类渠道投入是浪费。
- **诚实披露先例**：`docs/benchmarks/residual-context-occupancy.md` 承认 explore
  会话驻留上下文比 grep 代理多 ~80%（67k vs 18k tokens）——指标不利时披露而非隐藏。

## 2. 协议五条

### P1 双臂封 CLI 守卫（防侧信道）

控制臂（WITHOUT 臂）的评估环境**必须物理封掉被评估工具的所有触达面**，而非口头
约定"不要用"：

- 封 CLI：控制臂 shell 里被评估工具的命令不可达（PATH 剥除/别名拒绝/守卫脚本拦截），
  并对会话留痕做**事后审计**——若发现控制臂通过任何间接面（Bash/pip 装回/复制粘贴）
  触达工具，该臂样本作废重跑。
- 对 MCP 工具面评估同理：控制臂的 MCP server 配置里不注册被评估工具，且守卫审计
  覆盖"代理经由其他工具间接重建等价能力"的路径（如用 Bash 跑 vrp CLI——CLI 与 MCP
  共享 facts.db，二者必须同封）。
- 守卫失败=评估失败：宁可报废整轮样本，不可采信污染臂。

### P2 每臂 ≥2 次取中位

- 每臂至少跑 2 次独立会话（不同会话 ID、互不共享上下文），指标取中位数。
- 单次会话的代理行为方差大（同一提示词两跑可以一好一坏）；n=1 的"改进"不可信。
- 出现离群值时加跑至 3 次取中位，并在结果里披露极差——不悄悄丢弃不利样本。

### P3 三反馈指标（成功/失败都要度量）

对每臂会话记录三项，缺一不可：

1. **驻留上下文占用**（residual context occupancy）：任务完成后会话中驻留的
   token/字符量——工具若把上下文撑爆，后续轮次质量衰减是隐性成本。
2. **下一步动作充分性**（next-action sufficiency）：工具输出是否足以让代理直接
   产出下一个正确动作，而非还需回头 Read/重查——量化为"产出下一步前的补查次数"。
3. **字节分配效率**（byte allocation efficiency）：输出预算花在了会被告知/被使用的
   信息上的比例——截断告警、被忽略的段落都算浪费。

三项全是**反馈类**指标（描述工具对代理行为的实际作用），与任务成功率（结果类指标）
分开记录；工具可以"任务成功率持平但反馈指标全优"（更省上下文=可承载更长任务）。

### P4 低显著度渠道别投入

- 措辞/描述/字段重命名类微调（低显著度渠道）已被参照仓实测证明改变不了代理行为。
- 评估预算优先给**结构性变更**（工具面收敛/预算档位/成功形状错误契约）；措辞类
  变更不单独开 A/B，只在结构性变更的 A/B 里顺带观察。

### P5 诚实披露

- 结果文档必须披露不利指标（residual-context-occupancy 先例），禁止只报赢面。
- 样本量、臂间差异幅度、离群值处理全部写明——"导出与自己比"的循环完美门
  （BB3 铁律同源）在 A/B 面同样禁止。

## 3. 执行 checklist（未来 A/B 验收逐项打勾）

1. [ ] 控制臂 CLI/工具面物理封禁已布防（PATH/注册面），守卫脚本就位
2. [ ] 两臂任务提示词、环境、数据版本字节级一致（唯一差异=被评估面）
3. [ ] 每臂 ≥2 次独立会话，计划取中位
4. [ ] 三反馈指标采集面就位（会话留痕可回放统计）
5. [ ] 事后侧信道审计计划就位（控制臂触达检测）
6. [ ] 结果文档模板含不利指标披露栏

## 4. 范围声明

- 本协议约束**vrp 消费面产物的 A/B 验收**（dossier/评分/MCP 工具面/未来 fixpropose
  提案面的批间对比同样适用——新面首次验收时按 §3 打勾）。
- 不约束常规回归测试（pytest 面）——那是正确性问题，不是行为对比问题。

## 5. 脚本面诚实缓议

BB6 原文"协议文档+脚本，本地可执行"——**脚本面缓议**：本协议落地时 vrp 尚无正在
进行的 A/B 验收场景（dossier 面无近期大改计划），先写协议钉方法论；待首个真实
A/B 验收场景触发时再按 §3 checklist 补守卫脚本（触发驱动纪律，不造无人用的轮子）。
触发时脚本面预期形态：控制臂 PATH 守卫壳+会话留痕的侧信道审计器+三指标统计器。
