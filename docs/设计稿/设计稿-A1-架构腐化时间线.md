# 设计稿：A1 架构腐化时间线

状态：**待批准**（2026-11-19 起草；构想 v10 §A1"架构腐化时间线"落地稿；J8 增量已落——#190 是本稿回放调度的成本前提）

## 1. 现状与增量（诚实盘点）

- **雏形已在库**：fid_ledger（project/qualified_name/file_path/first_seen_at——身份史）；cochange（R2）已有 git log 挖掘全链（`git log --no-merges --name-only --pretty=%x1f%H%x1f%aI` → `parse_log`/`mine`，chg 计数可直接复用）；complexity 有 `py_cc`/`py_cognitive` 函数级度量；s2_deadcode.`dead_code_candidates` 纯 SQL 候选查询；scoring 有 indegree 面。
- **J8 使回放 affordable**：#190 实底 tsa 全量 27.1s→增量 no-op 6.6s（~4.1x）/改单文件 4.8s（~5.7x）——相邻历史样本多数文件字节不变，增量命中率结构性高。
- **缺三件**（=本稿范围）：回放调度（历史 commit 树物化+逐样本 ETL 驱动）、度量序列化存储、演化叙事渲染（"这个仓库哪天开始烂的"）。

## 2. 回放机制（正面回应"逐 commit 回放 ETL"）

### 2.1 采样而非逐 commit（采纳）

逐 commit = commit 数×ETL 成本（tsa 千级 commit 不可用，构想原文"慢仓采样"）；采样 N 点（默认 `--samples 20`）：`git rev-list --count HEAD` → stride=ceil(total/N)，恒含首尾（首=最早样本、尾=HEAD）。样本集是 rev-list 的确定函数。

### 2.2 单 detached worktree 串行推进 + J8 增量链（采纳）

`git worktree add --detach <tmpdir> <首样本 sha>` 一次物化，逐样本 `git checkout --detach <sha> --force` 推进同一 worktree——相邻样本仅变更文件换盘，未变文件字节原位 → J8 `_ContentHasher` wt_hash 命中 → 跳过重解析/重插。**用户工作树零接触**（worktree 在系统 temp，finally 删除）。备选 `git archive` 逐样本解包否决：每样本全树 IO，增量优势尽失。

### 2.3 链式单库推进（采纳）

单 tmp facts.db：样本 1 全量 → 样本 i 增量推进 → **每步推进后立即查度量向量**再前进。J8 D6 已证增量与全量逐表行集全等——链末库≈HEAD 树全量（时点列例外同 #190 裁定：created_at/first_seen_at 不参与）。每样本独立库否决：增量优势归零+库管理面翻倍。

### 2.4 已知成本风险（记档不阻塞）

worktree 内 `.vrp/` 首跑为空——CBM 索引每样本可能重建（文件清点+哈希，相对解析便宜）；D4 闸门（cbm_version/db_uid 漂移强制全量）在链库上不触（同库同 cbm）。dogfood 实测定真实命中率，不钉值。

## 3. 度量向量（学 Tornhill 定义）

每样本一记录，字段（全部从链库+git 历史可确定性导出）：

| 字段 | 来源 |
|---|---|
| files/loc/symbols/edges | 链库 count 查询 |
| edge_density | edges/max(symbols,1) |
| dead_code_candidates | s2_deadcode.dead_code_candidates 计数（只读） |
| births/deaths | 相邻样本 symbols fid 集差分（样本 1 births=全部） |
| scc_count | edges 表 file→file 投影 Tarjan 强连通分量（size>1 计数，stdlib ~50 行新算法面） |
| hotspot_top10 | Tornhill hotspot=chg×复杂度：chg=样本窗内该文件在 git log 出现次数（cochange.parse_log 复用）×文件 py_cc 和 |

**honesty 刻度**：hotspot 复杂度面 Python-only（complexity.py 现状）——多语言仓该列缺席记档不阻塞；scc 投影是文件级近似（函数级环归 s6/p4 管辖，不重复）。

## 4. 存储与产物

- **`.vrp/timeline.json`**：git 历史+参数的确定函数——固定键序/排序键/无 wall-clock 字段 → 同仓同 rev-range 同 N 字节级复现（静态产物红线）。
- **文本渲染**：每度量 ASCII 趋势列 + **转折点叙事**（相邻样本死代码/环数/耦合最大正向跳变，附 commit 对与日期——"哪天开始烂的"直接回答）。
- **不入 facts.db**：观测派生序列非实体事实（traces/perf.jsonl 先例）；schema 零动=OWNED/静态面红线零触；链库本身是 tmp 件用后即弃。

## 5. 红线核对

- 静态产物字节级一致：timeline.json 无时戳/确定序（§4）；不写用户 facts.db。
- 零第三方运行时依赖：git 子进程+sqlite3+stdlib Tarjan。
- 用户工作树零接触：detached worktree 在系统 temp，finally 清理（残留=盘垃圾+worktree 名冲突）。
- 无服务端/无前端构建链：不触。

## 6. 错误契约

- 非 git 仓/git 不可用 → 响亮 RuntimeError（cochange 先例：测量失败不是零样本——静默空曲线是说谎）。
- **单样本 ETL 失败 → 中止整回放**（报样本 sha+底层错误），不静默跳样本——跳样本=曲线缺口说谎；链断不可续（增量依赖前样本状态）。
- 采样少于 2 点（浅仓）→ 正常输出单点+明示"样本不足无趋势"。

## 7. 成本与测试面

- **实施面**：新模块 `vrp/timeline.py`（~250 行：采样/worktree 生命周期/链式推进/度量查询/叙事渲染）+ `cli.cmd_timeline`（`vrp timeline [--samples N]`）+ README 命令表。
- **新测试 ~10-12 件**（tmp git 仓固定 commit 史 fixture，零真实 sleep）：样本集 stride/首尾恒含确定性；链式 vs 逐样本独立全量**度量全等对拍**（J8 D6 同构核心件）；worktree 清理含异常路径；非 git 仓响错；转折点叙事已知答案；Tarjan 小图已知答案；hotspot chg 计数；单点仓明示；timeline.json 字节级双跑复现。
- **dogfood**：本仓+tsa 样本 20 计时与增量命中率记档（不钉值）。

## 8. 决策点（需批准）

- **D1 采样回放**：默认 `--samples 20`、恒含首尾；非逐 commit（§2.1）。
- **D2 单 detached worktree 串行推进+J8 增量链**：用户工作树零接触（§2.2）。
- **D3 链式单库步间查度量**：每样本独立库否决（§2.3）。
- **D4 产物=`.vrp/timeline.json` 确定性静态件+文本叙事**；不入 facts.db（§4）。
- **D5 度量向量 §3 十字段**；hotspot 复杂度面 Python-only 缺席记档；scc 取文件级近似。
- **D6 错误契约**：单样本失败中止全回放（跳样本=说谎）；非 git 仓响亮报错（§6）。
