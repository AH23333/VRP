## 2. 参照源码重读记实（file:line / 文档锚点）

- **coverage.py JSON 报告格式**（`coverage json` / pytest `--cov-report=json` 产物）：顶层 `{"meta": {...}, "files": {"<path>": {"executed_lines": [int...], "missing_lines": [int...], "excluded_lines": [...], "summary": {...}}}, "totals": {...}}`——`files` 对象逐文件，行号正整数数组；只消费 `executed_lines`/`missing_lines` 两字段（totals/excluded 不入存储——对账不需要）。
- **diff-cover 行级映射**（构想v10 §B4 轮子调研记档）：diff 行区间 × 覆盖行对账——本设计稿把"行区间"适配到符号级：符号 body 区间 vs executed/missing 行集合。**关键适配点（diff-cover 无此问题因为它不做符号映射）**：coverage.py 对"定义了但从未调用"的函数恒报 def 声明行 executed（import 时刻执行）——若直用全区间 `[start_line, end_line]` 会把"导入过"误判"测过"。规则修正见 §4。
- **traces 先例逐行重读**（vrp/traces.py:100-177）：形状违例整文件拒绝（诚实失败优于部分采信）/未解析名诚实上报（cap 10）不静默丢/per label DELETE+INSERT 幂等/收据 agreement 面。全部沿用。
- **R-AD/R-X 守卫约束**（tests/test_payload_discipline.py）：json.loads 结果消费必须 isinstance dict 守卫——`_load_cov_file` 逐层 isinstance 守卫（top dict/files dict/entry dict/lines list/int 逐项，bool 排除——`isinstance(True, int)` 为真）。

## 3. 导入面设计（输入/存储）

- **输入**：`vrp testcov <repo> --file <coverage.json> [--label L]`。文件为 coverage.py JSON 报告形状（§2）；label 默认 "unlabeled"（traces 同默认；coverage.json 无 label 字段——纯 CLI 参数）。
- **形状守卫**（整文件拒绝，traces 同哲学）：非 JSON / 顶层非对象 / `files` 非对象 / 键非非空字符串 / entry 非对象 / `executed_lines` 或 `missing_lines` 缺失或非数组 / 行号非正整数（bool 排除）→ SystemExit，零写入。
- **路径归一**：两侧 `\` → `/`（coverage.json Windows 产 OS 分隔符路径；facts file_path 前斜杠口径）。精确匹配不做前缀剥离（不猜相对锚——未匹配入 unresolved_files 诚实上报）。
- **存储表** `test_coverage`（facts_schema.sql 表区尾，drift_history 后）：

```sql
CREATE TABLE IF NOT EXISTS test_coverage (
    id INTEGER PRIMARY KEY,
    label TEXT NOT NULL,
    file_path TEXT NOT NULL,
    executed_lines_json TEXT NOT NULL,
    missing_lines_json TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
CREATE INDEX IF NOT EXISTS idx_test_coverage_label ON test_coverage(label);
CREATE INDEX IF NOT EXISTS idx_test_coverage_file ON test_coverage(file_path);
```

  - file_path 键（路径跨 etl 稳定 = co_changes/runtime_calls qn 键同哲学）；行数组 sorted-set 序列化（字节确定）；per label 整批替换（DELETE WHERE label → INSERT，幂等）；OWNED_TABLES + `"test_coverage"`（快照回灌存续——test_etl_preserve 集合断言同步）。
- **写入闸**：CLI 经 `_open_facts_rw`（ensure_schema 自愈 + M4 facts 新鲜度硬闸——陈旧库拒绝写入先重跑 etl；traces 同闸）。

## 4. 对账分类设计（五桶+悬挂计数）

**符号执行判定**（body 区间，diff-cover 行区间映射的符号级适配）：

- `executed := body 区间 (start_line, end_line] ∩ executed_lines ≠ ∅`
- `missed := body 区间 (start_line, end_line] ∩ missing_lines ≠ ∅`
- **start_line（def/class 声明行）本身不计**——coverage.py 对未调用函数恒报 def 行 executed（import 时刻执行），直用全区间会把"导入过"误判"测过"（§2 关键适配点）。
- `end_line <= start_line`（单行符号，body 空）→ 区间无行可命中 → executed/missed 恒 False → 落 undetermined 桶（诚实未定不猜）。
- bisect 单测（`bisect_right(lines, start)` 首个 >start 的行 ≤end 即命中）——O(log n) 每符号。

**五桶**（对象 = test_linkage 静态关联的目标符号）：

| 桶 | 判定 | 语义 |
|---|---|---|
| linked_and_covered | 有静态关联 ∧ executed | 关联真：测试确实执行了目标 body |
| linked_not_covered_measured | 有静态关联 ∧ 文件在覆盖运行 ∧ missed ∧ ¬executed | **假关联强信号**——"静态说有测试但从不执行"（B4 核心动机现形） |
| linked_not_covered_unmeasured | 有静态关联 ∧ 文件不在覆盖运行 | 范围信号（弱——覆盖运行没测到该文件，非假关联证明） |
| linked_undetermined | 有静态关联 ∧ 文件被测 ∧ ¬executed ∧ ¬missed | body 区间无任何覆盖数据（单行符号/全 excluded）——诚实未定 |
| covered_not_linked | ¬静态关联 ∧ executed | 静态漏关联（test_linkage 假阴性面——实际执行了但静态没关联上） |

**+悬挂计数** `linked_unresolved`：test_linkage 指向无现行符号行的 fid（etl 后应恒 0；非零即悬挂锚诚实计数）。样本 cap 5/桶（qn 回显——消费方免 join，traces 同哲学）；linked_unresolved 样本=fid 回显。

**已知局限（诚实记档，receipt note 明示）**：class 符号 body 含方法 def 行——import 时刻执行，class 符号"被覆盖"仅证明类体导入过而非方法被测（Function 符号语义最准）。
