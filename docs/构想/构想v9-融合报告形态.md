## 1. 目标与非目标

**目标**：

1. 单 HTML 静态融合报告：仪表盘入口 + 叙事主线 + 力导向图 + 下钻面板 + 对比节 + 数据切片，六节一页；
2. 三红线全守：静态产物、无服务端、无前端构建链（JS 允许——v8 §0.5 先例：红线是"无构建链"非"无 JS"）；
3. 全部交互客户端闭环：锚点导航、图点选、hash 路由、过滤分页——零网络请求；
4. 复现性：同 facts.db → 字节级同 fusion.html（数据 JSON 键序固定、产物无时间戳、头部带 git_head）。

**非目标**：

1. 不替代 SARIF（行级红线投影）与 repomap（AI 消费投影）——四投影分工不变；
2. 不做渲染引擎（不引入前端框架/构建链）；
3. 不做多页站点（v8 的站点化路线暂缓，融合优先验证单页形态）。

## 2. 融合架构（六节一页）

| # | 节 | 融合来源 | 内容 | 实现 |
|---|---|---|---|---|
| 1 | 仪表盘 | P6 | 指标卡（符号/边/findings/对账一致率/coverage gaps/slices）+ 聚合图（pathology 分布、kind top-N、边类型分布、CALLS 置信直方） | ECharts，全量预计算 |
| 2 | 叙事主线 | P1 | 总览→异常→证据→建议四段叙事，数字全部来自 facts.db 实算，证据芯片可点击跳转切片表并预置过滤 | 生成时模板化 |
| 3 | 结构图 | P5 | 目录级力导向图：节点=目录（size=符号数，色=病理密度）、边=跨目录 CALLS 聚合 | ECharts graph——布局 Python FR 确定性预计算（V-9.1），`layout:'none'`，标签全显 |
| 4 | 下钻面板 | P4 | 点图节点/表格行→右侧滑出：目录→top 文件/findings 分布/出入边；findings 行→锚定符号/位置/payload | 客户端 hash 路由 |

## 3. 技术底座（单库收敛）

- **ECharts 5**：仪表盘+力导向+分布图一库承载（echarts.min.js 内联进产物，约 1.05MB）；
- **pyvis 退役**：ECharts graph 力导向覆盖其能力（悬停/缩放/邻域高亮），少一个依赖面；
- **archify 链保留**：结构图/diff 图仍走现行 archify 生成链，融合报告中按节组件嵌入（后续实施项）；
- **无框架无构建**：原生 JS + ECharts 单库，模板为手写 HTML 字符串（非引擎）。

## 4. 数据预算（嵌入规模红线）

| 数据面 | 预算 | 超限降级 |
|---|---|---|
| 仪表盘聚合 | 全量预计算（服务端算好嵌入，几十 KB） | 无需 |
| 力导向图 | 目录级节点 ≤60，边=跨目录 CALLS 聚合 | 聚合加深（三级目录→二级） |
| 下钻面板 | 每节点预嵌摘要（top 文件/findings 分布） | top-N 收紧 |
| 数据切片表 | findings **全量嵌入**（V-9.1：原型 15,741 行 ~1.7MB；初版 cap=2000 因按病理序截断致 P1 独占配额，弃用） | 大仓超预算才 cap 截断（行内诚实标注 嵌入数/全量数），totals 恒真 |

大仓（66k 符号级）不做全量符号嵌入——全行明细走 facts.db/SARIF，融合报告承载"可验收的概览+可下钻的证据"，不承载全量数据（P11 范式的静态化边界）。
